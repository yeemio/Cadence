# ADR-0010 领域内核通用性纪律

状态：accepted（2026-10-24 Owner 指令定案："业务层面设计得更通用，不绑定死非标自动化"）
来源：总控基于既有决策链推导，Owner 认可（同日）

## 背景

S-mes 重构当前规格源来自机加工/非标自动化场景（活厂拆解）。Owner 要求产品不绑定死该垂直行业。
模块边界已天然通用（决策 22：模块边界 = 运营循环环节边界，九循环环节是离散制造通用动词）；
**绑定点只在模块内部的领域词汇、状态集与字段口径**。本 ADR 把通用性做成"晚绑定、便宜换"，
同时守住"先垂直打穿"的时序纪律（Owner：方向对别改，时序错必须改）。

## 决定（三条纪律）

### 1. 内核词汇白名单（business-core）

`business-core` 只允许**跨离散制造行业通用**的制造词汇（现集：Tenant / User / WorkOrder /
Dispatch / Report / Inspection / Operation / Event…；M2 按需增补 Item / Resource /
TimeEntry / CostObject 等，仍须过判定三问）。

行业专属概念进入任何包的代码/规格前，过**三问**：
1. 该概念是否只在单一行业有意义？
2. 能否重述为"通用上位概念 + 默认配置/规则"？（例：齐套 → 开工前置条件规则 readiness rule
   的默认实现；工序路线 → 路线/步骤序列 route/steps；外协价 → 成本口径包的一个口径）
3. 是否已有通用上位概念可挂靠？

三问任一通过通用化重述，即不得以行业原词进内核。

### 2. 状态集配置分离

"九态工作令"等状态集是**机加工场景的默认配置**，不是内核。business-core 只放状态机**机制**
（XState 包装、迁移守卫接口、版本化 machine 定义的数据形状）；状态集本身 = 版本化配置，
行业包可整体替换默认状态集。

### 3. 行业字段外置

行业差异字段只进**环节模块的版本化 schema**或**口径包**，禁止进 business-core 类型。
audit_status 合法值仍由各领域规格定义（见 contracts/evidence-columns.v1.md，本条与其一致）。

## 时序纪律（防过早抽象）

- 行业包 = **配置集 + 模块集**（经应用注册表挂载，ADR-0004），在出现第二个行业客户/线索前**不立项**
- M1/M2 仍按现有规格源（机加工/非标）打穿 P1；期间守本 ADR 三条（近零成本）
- FDE 垂直深度背书与 P1 两周节奏不为本 ADR 牺牲（五条经营纪律之三）

## 验收可检查化

M2 起的领域代码与规格，code-reviewer 按本 ADR 审查：内核出现行业专属词、状态集硬编码、
行业字段进内核类型，均判 REWORK。

## 后果

- 通用性晚绑定：第二行业接入 = 新行业包（预置状态集/字段口径/报表口径/专属模块），地基不动
- 与 ADR-0009 参照定案互补：快格云"应用中心分层（基础/专业/行业/定制）"形状正是行业包的挂载形态
- M2 规格写作约束：领域规格作者须在规格中区分"内核概念 / 模块 schema 字段 / 默认配置"三层
