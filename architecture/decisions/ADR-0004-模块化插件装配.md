# ADR-0004 模块化插件装配

状态：accepted（2026-10-23 Owner 定案，2026-10-24 入库）
来源：决策簿 V1.0 ADR-0004 / 交接文档 §7（模式采纳自 kuaigeyun-mes，Apache-2.0）

## 背景

Owner 要求模块化可选；报价单的可选模块行必须直接对应代码开关——商业包装与技术包装是同一张表。

## 决定

插件装配三层：

```
应用注册表 + NestJS 动态模块 + feature flag
├─ 基础层（必装）：core —— 组织权限 / 基础数据 / 工作台 / 待办 / 审批壳 / 扫码
├─ 九循环环节模块（按需启停）：workorder / listing / dispatch / reporting /
│   inspection / inventory / hours / costing / baseline
├─ 专业包（= 可选 13 项）：薪酬 / 报表口径 / 维保 / 图纸
└─ 行业包（未来）
```

模块边界 = 运营循环环节边界（OwlCodaE 场景链同款切法）；每模块版本化 schema。

## 后果

- packages/application 内按九模块分包，禁跨模块直接引用内部实现（经 business-core 合同）
- 专业包不能反向被基础层依赖
- 报价单变更 → 注册表变更，一一对应
