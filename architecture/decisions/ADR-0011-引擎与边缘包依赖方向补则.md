# ADR-0011 引擎与边缘包的依赖方向补则

状态：accepted（2026-10-25，M1 收尾波前置定案，总控依 Owner"继续迭代"指令制定）
来源：ADR-0003 依赖铁律的实施缺口——engine-* 与 integration-* 的消费方向原文未覆盖

## 背景

- 审批模块（application 层）需要消费 engine-flow 内核（XState 工厂/守卫/事件），business-store 需要实现 engine-flow 的存储端口——现行 `application-only-core` / `store-tier-edges` 规则禁止，导致审批纵贯线无法落地
- Web 壳需要消费 integration-scan（摄像头适配）/ integration-im（容器检测）——现行 `web-via-ui` 规则禁止

## 决定（两条单向补则，不引入环）

1. **engine-\* 是水平内核**：`application` 与 `business-store` 可依赖 `engine-*`（engine-flow / engine-reporting）；
   engine-\* 自身仍只依赖 business-core（不变）——方向 application/store → engine → core，单向无环
2. **apps/web 是前端组合根**：与 apps/server 对称，可消费 `integration-*` 边缘包（UI 侧适配器）；
   仍禁 application / product-ui 反向依赖 integration-\*（边缘词汇不进业务层）

## 后果

- .dep-cruiser.cjs 三条规则同步修订（application-only-core / store-tier-edges / web-via-ui）
- 审批纵贯线（application/approval → engine-flow）、存储端口实现（business-store → engine-flow 端口）、
  Web 扫码页（web → integration-scan）成为合法依赖
- 组合方向纪律不变：apps 组合一切、core 被一切依赖、无循环
