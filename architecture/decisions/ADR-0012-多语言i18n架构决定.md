# ADR-0012 多语言 i18n 架构决定

- 状态：**accepted**（Owner 2026-10-27 口头裁定"多线程推进"，依据调研定稿版 proposal）
- 依据文档：`architecture/i18n-multi-language-proposal.md`（v1.0，2026-10-27，含全部代码实证与证据索引；本 ADR 只登记决定，论证以 proposal 为准）

## 决定

1. **前端运行时：react-i18next**（否决 react-intl / lingui）。决定性理由：存量中文抽取迁移零编译链、Vite 双入口 MPA 各自 init、namespace 与模块化装配同构、JSON 资源可进 PWA precache。
2. **资源组织**：`apps/web/src/i18n/`（locales/zh-CN 权威源 + locales/en-US 骨架，缺 key 回落 zh-CN）；key 约定 `<namespace>:<域内路径>.<语义>`，禁止中文原文作 key。**product-ui 不引入 i18n 运行时**（非注释中文仅约 60 行且非用户文案，ui-tier-edges 规则不动）。
3. **后端错误策略：响应体增补语义化 `code` 字段 + 前端按 code 映射文案**；message 中文原文**一字不动**（中文测试断言零触碰）；未知 code 前端回落 message。服务端不引入 Accept-Language / locale 上下文。
4. **落库显示名三分类**：schema 层无动作（零中文字面值）；用户自建主数据名=业务数据**不翻译、不分列、不复制表**；系统生成文案落库（通知/待办 title 等）走**存储 key 化（titleCode+params）+ 渲染时翻译 + 存量原文回落**。
5. **语言范围**：zh-CN 完整（权威源，语义零变化）+ en-US 骨架（common/login/menu+高频面）；M3 点向客户后目标语言=填一份资源 JSON。
6. **切换与持久化**：localStorage（`smes.locale`，缺省 zh-CN，先例=token 会话同方案）；登录 bundle 自带切换器只挂 login+common namespace；`<html lang>` 同步。users 表 locale 列本期不做（M3 按需）。

## 实施波次（proposal §8 全文有效）

波 1 基础设施+登录面+壳（M）→ 波 2 高频面+错误链路 code 化（L）→ 波 3 长尾+落库文案 key 化（L）；同一 writer 面串行，波与波间按写入面互斥可与其他批次并行。

## 不做清单（本期）

RTL / 时区切换 / 后端 Accept-Language 出多语言 / 主数据翻译与 name-display 分离 / 多币种 / 多语言 URL 路由 / TMS 接入 / users.locale 列 / IM 卡片多语言——见 proposal §10。
