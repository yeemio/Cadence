## 审查问题

1. **多语言实际可用性**：中文语义与行为有无退化；双入口资源是否隔离；切换、持久化、菜单与错误链是否一致；code／message 兼容和存量通知回落是否真实成立。按 ADR 的英文骨架范围审查，不把用户数据中文或既定回落当作全站英文化缺陷。
2. **SP-3 真实保证**：两域密钥是否从配置贯通到实际消费者；非法配置是否拒启动；稳定密钥下的重启／适用实例读回是否成立，TTL、租户、访问和留痕是否保持。
3. **CM-1 生效位置与兼容**：用户实际加载的 HTML／静态入口和相应响应是否带头；CSP 是否匹配登录、桌面、移动和连接路径；不能靠 API 层头部或放宽所有来源冒充浏览器保护。
4. **裁-12 权限一致性**：核实结果是否绑定准确候选；通知是否在服务端按关联修订的现有 clearance／租户规则过滤，保留 `drawing:read` 门禁；不足许可用户是否仍能从响应获得受限通知或变更内容，有权用户与普通通知是否正常；实际存在的分页／计数与可见结果是否一致。界面隐藏和仅有截图不能证明服务端不泄露，单字段脱敏不能代替本包的可见性保证。已修复声明必须有相同候选的有效证据。
5. **岗位入口与业务链**：原岗位能否从工作令选择／上下文跳转完成清单与缺口核查；特采让步与判定撤销是否可从质检页面实际完成并核对结果；授权、无权、不适用状态和失败恢复是否可理解且仍由后端约束。核对这些具名入口逐项的现状、修复或复用证据，不以接口可用代替页面可用；特采、处置与入库语义未被擅自合并，判定撤销未扩成撤销完工。原角色交接保留失败／未执行分母；造厂、admin 全权访问和页面截图不能当全岗位通过；D-18 有真实数值证据或准确保留未验。
6. **交付材料与安装**：非开发者能否照说明操作；命令、模块、配置、已知限制与更新后的岗位操作是否与候选一致；干净环境是否使用本轮源码；单机／SaaS 关键差异是否有相称证据；说明完整不能代替实际安装结果。
7. **边界保持**：既有脏改、原 writer、冻结 PRD、租户／幂等／事件留痕不变量及恢复源是否保全；是否越过 SP-5／裁-11、特采入库联动、工作令编号、完工规则等待决，或真实客户、生产、外部调用及新增范围权限。

沿具名问题阅读实际调用者和证据，必要时在获准隔离环境补一个会改变裁决的检查；不扩大为全仓安全审计、全量 PRD 重审或生产演练。不修改代码、快照、基线或作者测试以使其通过。
