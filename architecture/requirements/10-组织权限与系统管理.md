版本：v1.0（2026-10-26 冻结）｜编写者：code-writer-pro（GLM-5.3，agentId 见交付回传）｜域码：SYS｜验收记录：ACCEPT（code-reviewer GLM-5.3 agent_de0a2a99，2026-10-26）

## 1. 域定位与边界

**身份**：全产品的基础运行层——登录认证与会话治理、用户/角色/机构/岗位主数据与三级权限判定、工作台待办与运营总览、审批运行时与审批流配置、菜单配置、站内通知、操作日志与模块启停证据，为全部业务域提供「身份 + 权限 + 待办 + 审批 + 审计」的横向能力。

- **In**（消费什么）：
  - 自管主数据：用户/角色/机构/岗位（本域 org 模块）、会话记录（本域 auth）；
  - 业务域事件：各域审批请求（七模块经端口发起）、各域事件点的待办派发与站内通知（工作令/质检/派工/故障派修等，详见各域分册）；
  - 全局写操作流（审计拦截器旁路收账，不参与业务事务）；
  - 总览四源读数：工作台待办（本域）、交付态势（13 册 WO）、质检汇总（17 册 RQ）、机加工时（19 册 HC）。
- **Out**（产出什么）：
  - 身份与租户上下文（AuthGuard 全端点收口）+ 三级权限判定（精确码 → 角色投影 → admin 放行）；
  - 会话令牌（登录/续期/登出/停用全端下线）；
  - 待办与站内通知收件（个人视角，联动业务闭环）；
  - 审批案件账本（事件事实源 + 案件投影）与租户级审批流配置；
  - 桌面/移动菜单树（可见性 = 接口可达性）；操作日志流水；模块启停存在性证据。
- **实现锚**：模块 `packages/application/src/{auth,core,org,workbench,approval,approval-config,menu-config,notifications,audit,demo}/`；页面 `apps/web/src/pages/{org,workbench,system,notifications,overview}/`；种子 `packages/business-store/prisma/seed.mjs`。本域无 m2 独立合同（属 core 基础层，ADR-0004），通用纪律随 `architecture/contracts/m2-drafts/README.md`（命令层/证据列/权限码风格/依赖铁律/多租户）。
- **非本域**：各业务域自身的审批业务语义（配件申请审批归 13 册、发料审批归 18 册——本域只供运行时与配置）；移动页面群呈现（21 册 MB——本域供同径端点）；IM/扫码/附件/打印（22 册 INT）；质检 KPI 与工时统计的取数口径（17/19 册——总览页只做四源聚合呈现）。
- **源文档对照输入**（本册精读范围，其余源文档不进本册对照）：
  - `工作台/管理工作台-开发文档.md`——运营总览 Tab（状态分布/12 日趋势跑批/质检 KPI/在制交付态势）+ 待办中心 Tab（10 步卡片 + 工作令维度全景），对照我方 overview/workbench 页；
  - `系统管理/移动端菜单-开发文档.md`——仅取角色授权树与产品包管理角度（S8），移动端页面本身归分册 21。

### 2.3 端到端场景走查

**场景 A · 新员工入职配权**：管理员建用户（设初始口令，scrypt 同源哈希落库）→ 角色与授权页按权限码期望态一次提交（增授/回收自动 diff）→ 员工登录拿会话与权限投影，菜单按可达性呈现。

**场景 B · 审批闭环**：业务域（如配件申请）经端口发起审批 → 建案落待审态并给每个审批人派待办（source=approval）→ 审批人在工作台/移动待办点入，按决策类（通过/驳回/上送/撤回）提交 → 本人该案待办自动完成、案件按配置推进 → 业务域消费结果回写自身状态。

**场景 C · 停用即下线**：管理员停用某账号 → 该账号全部会话即刻撤销（全端下线）→ 漏撤销的会话在续期口被「用户仍存在且 active」复查拦下（双保险）。

**场景 D · 晨会总览**：管理者登录即见四源总览卡（我的待办/交付风险/质检态势/机加工时净额）→ 下钻交付态势看九态分布与逾期分组 → 点质检四类下钻定位待检堆积 → 铃铛未读通知处理跨域催办。

**场景 E · 菜单与权限联动配台**：管理员在菜单管理页维护桌面/移动两配置集（节点挂权限码）→ 角色与授权页按码授权 → 用户登录后菜单按「令牌权限投影 ∩ 配置树」出树——不可达即不可见，无独立菜单授权面。

### 2.4 移动同径说明

工作台待办两读一写端点为移动同径消费（m.workbench / 移动待办，21 册 MB 呈现）；本域不设移动镜像端点。通知在移动侧经 21 册壳层入口消费同一收件箱端点。

## 3. 业务对象与状态机

### 3.1 领域对象清单

| 对象 | 粒度 | 说明 |
|---|---|---|
| UserAccount（用户账户） | 租户×用户名 | active 启停 + 口令哈希（scrypt 自述格式，盐随机）+ 角色绑定（经策略 g 规则） |
| RoleDefinition（角色） | 租户×角色名 | 元数据 + 该租户内直接授予的权限码集合（admin bypass 不入视图） |
| 策略规则（两形态） | 租户内 | grant-role（用户-角色）与 grant-permission（角色-资源-动作）两形态，同一写通路径（casbin autoSave → PolicyStore） |
| DepartmentMaster（机构） | 租户×机构 | parentId 树，服务端防环；不做删除级联与层级深度限制（M2 用户字段接线预留） |
| PositionMaster（岗位） | 租户×岗位 | 归属机构存在性校验 |
| Session（会话） | 租户×会话行 | 明文令牌只在签发响应出现一次；库存摘要、访问期/续期上界/软撤销时刻 |
| TodoItem（待办） | 租户×人×条 | 指派人 + 来源模块码 + 引用（refType/refId） |
| Notification（站内通知） | 租户×收件人×条 | 标题/正文 + 来源 + 引用 + 服务端已读时刻 |
| AuditLog（操作日志） | 租户×条 | append-only：操作者/方法/路径（去查询串）/摘要/时刻；不含载荷全文 |
| MenuConfig（菜单配置集） | 租户×配置集键 | 桌面（default）与移动（mobile）双配置集；nodes 树整集管理 |
| ApprovalFlowConfigRecord（审批流配置） | 租户×行 | flowId 业务键不可变；租户内至多一行 active |
| ApprovalCase（审批案件） | 租户×案 | 业务对象引用（subjectRef）+ 案件行投影（乐观版本）；事件账本为事实源 |

持久化对象随 m2 通用纪律带证据公共列与 append-only 事件面（evidence-columns）；本域状态机类对象（审批案件）走 engine-flow 配置形态、待办/通知为轻量两态行、会话/日志为 append-only 事实行。

### 3.2 状态机

| 状态机 | 迁移链（默认配置） | 语义要点 |
|---|---|---|
| 审批案件 | 建案 →(提交)→ 已提交 →(进审)→ 待审 →(决策四类：通过/驳回/上送/撤回)→ 各终态或流转 | engine-flow 配置驱动，默认配置起步、租户可整体替换（见 3.3）；迁移规则反查配置取命令动词，守卫拒绝 = 状态冲突不落账 |
| 待办 | open →(本人完成)→ done | 完成幂等、仅限本人 |
| 通知 | 未读 →(标记)→ 已读 | 标记幂等；已读时刻服务端事实 |
| 会话 | 有效 →(到期/登出/停用)→ 撤销 | 软撤销；访问期与续期上界双时刻 |

状态集词汇为模块 schema、状态集语义为内核（ADR-0010 三层口径）；除审批案件外本域状态机均为固定轻量两态/三态，不开放租户自定义。

### 3.3 配置驱动的审批流（口径）

案件状态集与迁移由审批流配置文档定义（engine-flow 权威校验），租户内单启用行即当前生效配置；每次发起/决策按租户现解析——配置换代后在途案件由事件重放守卫兜底（重放态与案件行不一致即状态冲突拒绝，不静默漂移）。

### 3.4 种子策略形态与判定链

| 策略形态 | 含义 | 种子实例（seed.mjs） |
|---|---|---|
| grant-role（g 规则） | 用户 × 角色绑定 | admin、demo-admin → admin 角色（域内全量放行）；approver 用户 → approver 角色 |
| grant-permission（p 规则） | 角色 × 资源 × 动作精确授权 | approver 角色 → approval:read / approval:write / workbench:read |
| 无策略 | 登录可、业务面全拒 | viewer（e2e 的 403 证据身份） |

判定链（每请求）：令牌解析会话 → 三级权限判定（用户直接/角色投影/admin 放行）→ 菜单可见性与端点可达同源。种子脚本与运行时口令哈希同形状同源（seed 到运行时只有一种格式）。

## 5. 业务规则与口径

1. **身份三不进**：租户身份、操作者身份、收件人身份一律从上下文/请求身份进，不从请求体、参数或查询串自报（ADR-0005；唯一例外：建待办/发通知的指派人/收件人是业务载荷，非身份自报）。
2. **会话语义**：访问期 8h / 续期窗口 7d 自首签起算不滑动；续期 = 撤旧签新（轮换）并继承窗口上界；明文令牌只在签发响应出现一次，绝不落库/进日志；停用即全端下线 + 续期复查双保险。OAuth 外部身份（企微/飞书换码）为已留接口缝、不实装（auth.controller.ts:21-24）——是否排期由 Owner 点向，不预造实现。
3. **授权写通单径**：正式端点与开发态策略钩子写同一事实源（casbin autoSave → PolicyStore），无双轨；用户-角色与角色-权限均为期望态全量提交（diff 后增授/回收），幂等可重放，不做增量补丁。
4. **总览数据权限**：源文档 V1「不做数据权限过滤、统计全量」——我方以实态为准：待办/通知按本人，交付/质检/工时按租户内业务事实聚合（租户收口），不做个人维度二次过滤；菜单可见性挂 workbench:read 入口码，页面数据另涉工作令/质检/工时三码，部分权限用户进入时整页明示失败来源（不虚构后端没有的复合码，menu.ts:20-23）。
5. **总览口径取舍（对源文档）**：风险口径我方为逾期/临期/正常（按交付倒计时现值分组），不用源文档 ≤30/31-60/>60 阈值；九态分布为全量口径含终态零填充；质检 KPI（待检三源按图号去重等）与工时净额口径的取数定义归 17/19 册，本册只定聚合呈现；趋势统计重定义基于我方事件账本/报表口径，不落源文档跑批表形态（RREQ-SYS-028）。
6. **审批配置换代**：租户单启用收口；配置仅对新案件生效语义由「每次发起/决策按租户现解析」实现，在途案件重放不一致即拒绝（fail-closed），不存在静默漂移。

## 6. 跨域关系

**谁触发我（上游）**
- 全部业务域写端点 → 审计拦截器旁路收账；全部受保护端点 → AuthGuard 会话判定 + 三级权限判定。
- 七业务模块（workorder/listing/dispatch/reporting/inspection/baseline/inventory）→ 经端口发起审批案件（RREQ-SYS-034）；各域事件点 → 待办桥建待办（RREQ-SYS-023）与通知端口代发（RREQ-SYS-051）。
- 13/17/19 册 → 总览四源之三源读数（本域只做聚合呈现）。

**我触发谁（下游）**
- 审批决策 → 经各域端口回写业务状态推进（明细见各域分册）。
- 待办/通知 → 个人收件（Web 工作台/总览/铃铛 + 21 册移动待办同径端点）。
- 用户停用 → 会话全端下线（联动全部在线端）。
- 菜单配置集 → Web 壳菜单树/路由守卫 + 移动页面注册表（21 册消费）。
- 权限码体系 → 全部域控制器的门禁语义（99 码开放式的本域 19 码 + 各域码）。

**关键数据流小结**
- 审批流：业务域命令 → 发起端口 → 案件 + 事件账本 + 审批人待办 → 决策（事件 → 决策记录 → 案件行乐观推进）→ 待办自动完成 → 业务域消费结果。
- 总览流：四源各域读端点 → 视图模型聚合（坏形状拒绝）→ 总览卡与下钻；单源失败整页明示失败来源，不部分虚构。
- 配权流：角色授权期望态 → 策略写通 → 下次请求判定即生效；停用 → 会话撤销 → 令牌即刻失效。
