## 1. 域定位与边界

**身份**：移动端是 Cadence 同一 Web 应用的 PWA 呈现面（`/m` 路由组），面向车间现场的单手/扫码作业形态——固定信息架构「4 底部标签 + 11 子页」，桌面端是全功能管理面，移动端是现场高频动作面。

- **In（消费）**：各业务域后端端点（报工/核查/质检/配件/库存/盘点/工时/工作令/故障/待办——后端不设移动镜像端点，移动页打同一模块端点）；权限码会话投影；菜单配置（menu-config scope=mobile）；统一扫码会话与 PWA 离线基建（22-INT 册定义，本册消费）。
- **Out（产出）**：移动页面群（16 页组件 + 路由注册表 + 装配）；报工提交的离线入队与恢复重放；coverage §2 移动端 29 项标准项（#105-#137）的"对应端呈现"。
- **不产出**：业务规则与状态机（归各域分册：报工五态归 17-RQ、配件五态归 18-IS、盘点四态归 15-IV 等）；扫码/PWA 能力本体（归 22-INT）。

## 2. 角色与场景

移动端角色以演示口径的两类现场身份为主（权限码实态锚点：`packages/product-ui/src/session.ts` 种子）：

| 角色 | 权限码（移动相关） | 场景 | 可见移动页 |
|---|---|---|---|
| 操作员（operator） | workbench:read / report:submit / report:read / hours:read / stock:read / workorder:read / parts:read+request / fault:report | 工人现场作业：扫码报工、查自己工时、查库存、发起配件申请、上报设备故障、查进度与自己的报工记录 | m.workbench / m.report / m.hours / m.stock + 子页 m.parts / m.fault / m.progress / m.op-progress / m.mine |

- 可见性=权限码投影（精确码匹配 + admin 全量放行）：标签/入口不足码不渲染，页面级数据边界由服务端 403 兜底——与桌面"菜单可见性=接口可达性"同语义。
- 其他演示身份的移动行为：admin 以 `*` 全量放行（四标签+11 子页全见）；无任何移动权限码的角色（如 viewer）底部导航全隐——注册表测试断言的"零匹配全隐"形态（apps/web/tests/mobile.test.ts：单码窄授权只见对应页、admin bypass 全见同文件断言）。
- 入口（桌面/移动）：
  - 移动主入口：安装态 PWA 图标直达 `/m`（start_url）；浏览器访问 `/m` 同径（窄域回落，见 RREQ-MB-003）。

  - 桌面端不经由本册页面群——桌面管理页是各域分册的呈现面；同一命令端点双端同径。

## 5. 业务规则与口径

1. **信息架构冻结**：底部标签四项（工作台/报工/工时/库存）S3 起冻结不再增项（≤5 上限预留）；新页一律进子页表，入口走工作台快捷区。页面码守 ADR-0010 通用词纪律（m. 前缀是路由组命名空间非业务词）。
2. **权限口径**：移动页权限码与对应后端控制器 `@RequirePermission` 同码——动作页挂动作码（m.report→report:submit 先例）、查询页挂读码；admin 全量放行。源文档"administrator 不特殊放行"不采纳（以我方实态为准，取舍：admin bypass 语义全系统一致）。
3. **移动与桌面同径**：后端不设移动镜像端点，移动页打同一模块端点；命令面复用桌面 API 数据层，读取面经 product-ui 视图模型钉形状（坏形状抛错不静默）。
4. **菜单配置 fail-open**：移动菜单配置服务不可用时回注册表全量（与桌面侧栏同取舍）；快捷区核心四项不受配置管辖。
5. **离线取舍**：仅报工提交离线入队；恢复后人工确认重放不自动放；队列上限 drop-oldest（旧条牺牲换新条必达）；幂等键同源防重放重复。
6. **呈现形态取舍**：源文档移动场景载体是微信小程序（uni-app + applet 前缀 API），我方为同代码 PWA（ADR-0006）——形态以我方为准，功能语义差异按 S6/S7 逐项登记。
7. **取数口径引用**（定义归各域册）：库存可用量=总量−预占；工序进度净额=已报+已核查链尾合计（撤销不计）；我的工时=本人已审核净额；"本人/仅本人"边界均为服务端数据级合同，前端不做信任过滤。
8. **写命令乐观锁**：核查/配件审批/质检判定/盘点录入均携带行 objectVersion 作 expectedRevision（移动与桌面同命令同锁）。
9. **验收锚点约定**：16 个移动页组件均在文件头注自标覆盖项号（如 VerifyPage 头注 111-114、MinePage 头注 #136+#116），验收时逐页读头注行与所属标准项号核对一致（终排口径，coverage §5）；e2e 走查以 mobile-shell.spec.ts（壳+工作台）+ mobile-subpages.spec.ts（子页逐页渲染）为准。
