## 1. 产品定位

Cadence 是一套**自研的机加工制造执行系统（MES）产品**——面向单件/小批量、按工作令组织的机加工与装配制造企业，覆盖从工作令下达、清单展开、库存核查、采购、派工、报工、质检、入库、发料到工时成本与售后的全业务闭环。

- **全新产品**：不是任何现有系统的替换或迁移；以雇主侧 73 份开发文档为需求输入对照源，全部功能以我方产品语言独立定义（本体系各分册）。
- **双交付形态**（ADR-0005）：单机买断版（单租户，开箱即用）与 SaaS 订阅版（多租户，行级隔离 RLS + 域名路由），同一产品两种部署。
- **模块化产品**：27 个业务模块按需启停（`MODULES_ENABLED`），缺省最小集（core/org/masterdata/workbench/approval/demo），按客户订购范围装配。
- **双端**：桌面 Web 管理端（45 业务页面）+ 移动端（PWA，4 主页签 + 11 子页，扫码报工支持离线）。

## 3. 角色与权限模型

- **权限码体系**：开放式品牌化权限码 `module:verb`（如 `workorder:transition`、`stock:receive`），全系统约 99 个；权限判定三级——精确码授权 → 租户内角色投影 → admin 角色全量放行；菜单可见性 = 接口可达性（桌面菜单码与后端权限码同源）。
- **标准角色**（种子账号，口令统一演示口令）：
  - **admin**——租户管理员，域内全量放行；
  - **approver**——审批人（审批读写 + 工作台），演示精确授权形态；
  - **viewer**——只读观察者（无策略，演示权限拒绝形态）。
- **演示角色口径**（零数据库形态）：组织管理员（主数据与组织管理 15 码）、操作员（车间岗位读码 + 报工提交等现场写码）、班长（报工核查/配件审批/质检判定/收发存全径——"单班长兼质检与库管"的小厂口径）。
- **移动端角色**：以班长/操作员为主（现场动作：报工/核查/质检/入库/移库/盘点/故障上报）。

## 4. 业务主流程链（产品主线）

```
工作令（下发）→ 四类清单展开（生产购置/标准件/电气/设备采购）
  → 库存缺口核查（利库/预占）→ 采购申请 → 采购订单 → 收货 → 采购质检 → 入库
  → 派工（自制/外协/装配电气/零工）→ 报工 → 报工核查 → 质检（自制/外协/采购）→ 入库
  → 发料（装配/电气任务，两段预占）→ 齐套核查 → 装配交付
  → 售后（派工/报工/报销/配件）
横向贯穿：工时归集 → 项目成本六块 → 薪酬核算；报表/指标/大屏；移动端现场作业；审批/待办/通知
```

## 5. 全局行为约定（产品语言）

以下约定适用于所有分册，各分册不再重复：

1. **多租户隔离**：所有业务数据按租户隔离（SaaS 形态行级隔离；单机形态单租户缺省）；跨租户访问一律拒绝（fail-closed）。
2. **模块化装配**：功能以模块为装配单位；未启用模块的接口不可达；核心模块（core）不可缺省。
3. **命令幂等**：所有写操作以幂等键提交，重复提交不产生重复业务效果（同一幂等键的重复提交返回原结果或显式状态拒绝，不产生新业务事实）。
4. **证据留痕**：业务事实不可变记账（事件账本），操作日志可查询；"谁在何时对什么做了什么"可追溯。
5. **审批可配置**：审批流（多级/会签等）运行时配置驱动，案件进入待审即推待办，决策后待办联动闭环。
6. **待办与通知同源**：待办工作台、通知中心、移动端工作台共享同一待办事实源。
7. **附件统一管理**：业务附件统一元数据 + 对象存储端口（可替换存储后端）；附件挂接于具体业务对象。
8. **删除与修正语义**：业务修正以冲销/修正版链表达（不篡改原行）；删除语义（物理/逻辑）以各域合同为准，被引用数据受删除保护。
9. **量纲约定**：时间类计量以分钟（整数）为最小量纲、金额以分（整数）为最小量纲，展示层换算。
10. **界面通用行为**：列表分页查询、组合筛选、导出（Excel 族）；导出与打印能力由各域按需声明。
