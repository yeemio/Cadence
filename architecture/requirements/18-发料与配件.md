# 18 发料与配件

版本：v1.0（2026-10-26 冻结）｜编写者：code-writer-pro（GLM-5.3，agentId 见交付回传）｜域码：IS

## 1. 域定位与边界

**身份**：生产与售后两条物料发放链路——生产发料（派工驱动的发料任务 → 去发料 → 确认发料 → 发料记录/撤销，含库存预占联动与快递发货头）+ 配件申请（售后配件申请 → 审批 → 发货出库联动）。

- **In**：
  - 派工事件：装配/电气派工成功 → 生成任务；撤销派工 → 清理判断（系统钩子，非人工触发）；
  - 四类清单需求行：零件/标准件/电气件/外购设备，含来源 origin（production/aftermarket）与利用库存/采购入库完成量；
  - 库存面：预占锚点（工作令+设备+物料三维）、料品可用量、库位结存（经端口读写）；
  - 工作令状态与项目经理（配件申请准入与审批待办）；操作工人/计划开完工（任务头快照）。
- **Out**：
  - 发料任务与明细子行（四数量实时视图）；
  - 发料记录（发前快照 + 库位扣减回执 + 来源拆分两段）与快递单发货头；
  - IssueConfirmed/IssueRevoked 域事件（BusinessEvent + Outbox）；
  - 配件申请五态流转与发货出库指令（requestId 幂等）；
  - 项目成本材料段事实（经 U7 取数端口供 costing 读取——归 19 册）。
- **边界**：库位结存/料品三账的物理扣减归 15 册 inventory（本域经端口下发指令）；设备清单行锁定与非标入库撤销门禁是本域定义的守卫、落点在清单/库存册（见 §7 D-IS-04/D-IS-05）；发料桌面页面归 D-IS-01 待办，本域现役形态是后端接口面。

**两条链路一句话**：

- **生产发料**：装配/电气派工成功 → 按工作令+设备+派工类型自动生成发料任务并补全子行（排除配件来源行）→ 仓管在去发料页按类别 Tab 勾选行、（标准/电气）配库位分配 → 确认发料建记录快照、库存端口扣减、来源两段拆分 → 撤销派工前未发料的任务随派工清理；已发料的走发料记录整单撤销原路回滚。
- **配件申请**：售后/现场对在役工作令发起配件申请（建单即提交）→ 项目经理一级审批 → 通过后发货联动库存出库 → 收货态由库存收货联动驱动；多级审批、特批、清单入单、跟进/收货链为 S6 待实现增量。

## 2. 角色与场景

**主流程走位**（生产发料）：派工员在 16 册完成装配/电气派工 → 系统钩子自动生成/补全发料任务（无需人工建单）→ 仓管按任务进入去发料页，按 Tab 浏览四数量、勾选可发行、为标准/电气行配库位 → 确认发料（一单一类别）→ 记录/快递头落库、任务进度重算 → 误发由主管整单撤销回滚。**配件申请**：售后人员在桌面或移动端对非终态工作令发起申请 → 项目经理在待办/审批页决策 → 通过后仓管发货（联动出库）→ 库存收货侧驱动收货态。

| 角色×权限码 | 场景 | 入口 |
|---|---|---|
| 仓管/物流（issue:read） | 查发料任务/去发料页明细/发料记录/快递下拉 | 接口面（无独立桌面页，D-IS-01） |
| 仓管/物流（issue:write） | 派工同步补发/清理钩子、确认发料 | 接口面；正式触发走派工钩子（U6 #29 接线） |
| 仓管主管（issue:revoke） | 整单撤销发料（原路回滚） | 接口面 |
| 售后/现场（parts:request） | 发起配件申请（建单即提交）、发货联动出库 | 桌面 workorder/PartsRequestsPage；移动 m.parts（#117） |
| 项目经理（parts:approve） | 配件申请审批（approve/reject） | 桌面 PartsRequestsPage；移动 m.parts-approval（#118） |
| 查询方（parts:read） | 配件申请列表/详情（含状态过滤） | 同上桌面页 |

场景注记：① issue 域现役无桌面页面——去发料/记录/快递的全部交互以 HTTP 接口面供前端（D-IS-01 页面群未建），移动端亦无 issue 页；② 配件申请双端在役（桌面 + 移动两页）；③ 系统钩子操作（派工同步/清理）不占人工角色，操作者记系统账号。

权限码实态：`packages/application/src/issue/issue.controllers.ts:66-188`（issue:read/write/revoke——读查/确认与同步/撤销三分）；`packages/application/src/workorder/workorder.controllers.ts:201-243`（parts:read/request/approve；shipment 复用 parts:request）。权限语义边界：issue:write 同时覆盖系统钩子面（sync/cleanup）与人工确认面，正式触发走派工钩子、HTTP 面作联调与运维补发兜底。

## 3. 业务对象与状态机

实现真源：u-wave `CONTRACT.md` U1 节；模块 `packages/application/src/issue/`、workorder 域 parts 子面。

| 对象 | 定义 | 状态/关键规则 |
|---|---|---|
| 发料任务 IssueTask | 派工维度的发料工单；唯一维度=工作令+设备+派工类型（装配/电气）；归拢单 rollup=true 一工作令一条、设备维空 | not-started / issuing / done——由汇总推导非状态机（issue-config.ts:58-93） |
| 发料子行 IssueTaskLine | 类别 part/standard/electrical/equipment（镜像四类清单 kind）；落库仅 模块/名称/图号/总需求量+来源行/物料锚点 | 四数量（已发/待发/已预占/当前可发）实时计算不落库（issue.service.ts:945） |
| 发料记录 IssueRecord | 一次确认发料的事实快照；一条记录一种 lineKind | active / revoked（撤销后退出已发累计） |
| 库位扣减回执 | 标准/电气行按库位的出库分配与两段拆分（预占消耗/可用消耗），issueKey 锚定 | 撤销按同一 issueKey 原路回滚 |
| 快递单 IssueExpress | 发货头（单号/发货人/发货时间/图片引用 ≤6）；确认时携带、复用同单号 | 撤销后无有效记录引用则删除 |
| 配件申请 PartsRequest | 售后配件单（单物料行：itemId+quantity）；建单即自动 SUBMIT | draft（瞬态初值）→ submitted →（approved｜rejected 终态）→ shipped → received 终态（workorder-config.ts:118-158） |

**状态流转图**（产品语言；实现细节见合同与模块注释）：

```
发料任务（汇总推导，非状态机）            发料记录（投影态）
┌ 无有效发料记录 → 未开始                 ┌ active（有效，计入已发累计）
│ 首次确认发料   → 发料中    ──确认──→   │   │ 快照：发前四数量+本次+发后
│ 参与类别行均已发≥总需求 → 已完成         │ 整单撤销（active-only，乐观锁）
└ 撤销派工：未开始才连带删除；             └ revoked（退出已发累计；标准/电气
  已发料任务阻断整批清理                      按 issueKey 原路回滚库存）

配件申请（状态机，engine-flow 配置先行）
draft ─建单即SUBMIT→ submitted ─approve→ approved ─SHIP(联动出库)→ shipped ─RECEIVE(库存收货联动)→ received(终态)
                         └─reject→ rejected(终态)      ↑ received 驱动接线未落（RREQ-IS-034 部分实现）
```

**关键字段面**（产品视角；表结构归合同层 schema.prisma 五 model）：

- 任务头：任务号/维度四元组（工作令、派工类型、设备维、归拢标记）/计划开完工/操作工人/触发锚点（triggerRefs 保留首次派工锚点）/汇总冗余列（状态、总需求、已发、完成时刻）；
- 子行：类别/来源清单行/物料锚点/模块/名称/图号/总需求量；四数量不落库；
- 记录头：记录号/任务快照（任务号、工作令、维度）/发料类别/发料时间与人/快递引用/总数量；
- 记录明细行：发前已预占/发前已发/发前可发/本次/发后已发/发后待发六量 + 预占消耗/利用库存消耗两段 + issueKey + 库位分配回执；
- 配件申请：工作令/物料/数量/申请人/备注/状态机版本/发货单号回填。

## 5. 业务规则与口径

1. **生成口径**：任务只由派工动作生成（系统账号信封），不做人工建单；同步幂等（operationId + 维度 find-or-create + 行级去重补全）。装配派工按自制设备逐台建单+整线另建归拢单；电气按电气清单全部设备逐台建单。
2. **四数量口径**（实时、发料校验与快照同一次读取）：
   - 已发=有效（active）记录明细累计；待发=max(总需求−已发, 0)；
   - 非标 可发=预占−已发（负=数据错误后端阻断）；标准/电气 可发=min(预占+料品可用, 待发)；外购设备 可发=min(待发, max(0, 预占−已发))；
   - 预占锚点=工作令+设备+物料三维汇总（外购设备=利用库存+采购入库完成）。
3. **确认校验顺序**：行归属与类别 → 物料锚定（标准/电气，先于数量报根因）→ 数据错误（非标负可发）→ 本次 >0 → ≤可发 → 快递头一致性（纯读预检）→ 幂等记账 → 端口扣减 → 投影 → 事件。端口拒绝时整单 rejected 返回、operationId 已占用（与 inventory 深校验取舍一致：端口是扣减权威，无先读预演面）。
4. **来源拆分两段**：标准/电气=预占消耗/可用消耗（按库位回执）；非标=预占冲减+自制余量不落库；外购设备=利用库存冲减+采购入库份不落库。均按「清单当前量−未撤销发料已分摊」剩余额度、单确认内按行序滚减。**与源文档差异**：源非标拆成品/半成品预占两列，我方实态为单一预占消耗列（半成品维未建）——按实态取舍，若 19 册成本材料块需要两段再扩列（登记开放问题）。
5. **撤销口径**：整单、active-only、乐观锁；标准/电气按 issueKey 原路回滚（回滚后写失败属数据级中断人工对账）；非标/外购设备不回冲库存，仅已发累计退出。
6. **快递单口径（实态边界，与源差异）**：源文档快递头为配件发料专属、唯一性按「申请或任务+单号」；我方实态为面向全部发料类别的通用发货头、唯一性按「工作令+单号+发货头一致」复用。按我方实态为准登记；若配件链路（D-IS-02）落地需按申请维收紧，回总控裁定。
7. **配件口径（与源六态差异）**：源=草稿/审批中/已驳回/处理中/已发货/已完成六态+三级审批；我方实态=单级审批五业务态（submitted/approved/rejected/shipped/received），建单即提交无草稿停留、无驳回后编辑重提。S6 增量落地时按源口径扩展，编号已占（S6）。
8. **词汇纪律**：issue/task/line/record/express 为离散制造通用词（ADR-0010）；源文档 FL-/spa_ 词汇不进我方词汇面。
9. **待发状态三档口径**（去发料筛选）：有效可发=min(max(当前可发,0), 待发)；无可发=有效可发 0；全部可发=有效可发 ≥ 待发；部分可发=介于两者。模块/名称先过滤，待发状态在四数量算出后过滤再分页（四数量只算当前页）。
10. **单号口径**：任务号前缀 ISS-ASM-/ISS-ELEC-/ISS-ASM-ROLLUP-、记录号 ISS-REC-，全串唯一由 uuidv7 尾段保证、不设计数器（人读可辨即可）。
11. **输入规模上界**：单次同步设备引用 ≤200、单次确认行 ≤500、单行库位分配 ≤50、数量 ∈(0,1e9]、发货图片引用 ≤6 张——超出即拒绝（issue-config.ts:118-130）。
12. **幂等与并发**：全部命令走 smes.command.v1 信封（operationId 幂等 + expectedRevision 乐观锁）；创建族命令（sync/confirm/cleanup）expectedRevision 须 initial，revoke 须当前版本。汇总写入/撤销写入的并发冲突窗口抛数据级中断人工对账（内存路径不可达，PG 合流以事务收口）。
13. **配件守卫**：终态工作令不再接受配件申请；配件审批/发货/查询各挂独立权限码；发货出库端口按 requestId 幂等（重试不重复扣减），端口拒绝则命令整体 rejected 不落任何账。
14. **归拢与设备名展示**：归拢单设备维为空，列表/详情设备名取子行名称拼接（不按设备维反查）；按设备筛选可命中归拢子行来源行。关联派工单号：我方任务只保留首次派工锚点（triggerRefs），实时解析「已派工/进行中/已完工派工单号、撤销后移除」是展示层行为，归 D-IS-01 页面项裁定。
15. **快递图片口径**：发货图片只存引用串（对象存储零依赖，≤6 张），本体上传/下载归 22 册附件域（ObjectStoragePort）——源文档「公用桶直链」细节在 Cadence 由附件域统一承载。
16. **多租户**：issue 五表与 parts 投影全表 RLS 行级隔离（rls/tables.ts）；跨租户读写不可达（测试覆盖跨租户隔离）。
