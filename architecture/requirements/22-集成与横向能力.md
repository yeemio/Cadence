# 22 集成与横向能力（INT）

版本 v1.0（2026-10-26 冻结）｜编写者：code-writer-pro GLM-5.3（agentId 见交付记录）｜域码 INT

## 1. 域定位与边界

一句话身份：为全部业务域提供的**横切基础设施面**——附件、扫码、打印、IM 消息、PWA 离线壳、演示与模块化启停，均为"多模块消费的通用能力"，不含任何单一业务域语义。

- **In（消费什么）**：core 的身份/租户（AuthGuard + TenantContext）；business-store 的持久化注入位；各业务域的业务对象主键（bizType+bizId 挂附件）、打印文档（外协加工单）、通知事件（notifications 出站）；部署环境配置（对象存储根目录、SMES_IM_\* 凭据环境变量、MODULES_ENABLED）。
- **Out（产出什么）**：附件元数据与短时只读下载引用；扫码结果（三档降级链）；打印任务受理回执；IM 文本/卡片消息渠道；PWA 安装与离线壳；模块装配清单与演示端点。
- **边界**：移动端离线**业务**细节（离线队列/补录报工）归分册 21，本册只定义 PWA 能力面；大屏**业务面**（KPI/聚合口径）归分册 20，本册只登记其 WebSocket 推送通道（集成侧，A8）；站内消息中心归分册 10（SYS/notifications），本册只定义 IM 外部渠道；模块化启停的产品级语义属总纲（01），此处按实态定义能力条目，总纲冻结后以其为准改引。

## 2. 角色与场景

| 能力 | 角色（权限码） | 场景与入口 |
|---|---|---|
| 附件 | 任意业务用户（`attachment:read` / `attachment:write`，按角色授予） | 在工作令、采购合同、送货单、报工等业务页挂取/删除/下载附件（业务页消费接线待后续波）；无独立菜单 |
| 扫码 | 车间/仓管用户（`scan:read`） | 桌面 `/scan` 扫码页（menu.ts:133-139）；移动端 `/m` 报工页复用同一会话装配 |
| 打印 | 外协派工管理员（dispatch 域权限） | 外协加工单打印（dispatch 域端点 → 打印受理面） |
| IM | 全体通知接收人；渠道由部署配置 | 待办/点名/派修等通知事件 → 站内中心（分册 10）+ 可配 IM 外部渠道 |
| PWA | 全体 Web/移动浏览器用户 | 安装到主屏、断网打开离线壳 |
| 演示/模块化 | 实施与运维（部署期配置 MODULES_ENABLED） | 开箱演示与按报价单裁剪模块装配 |

入口分三层：桌面菜单（/scan 等，menu.ts 注册表）；移动路由组 `/m/*`（复用扫码会话等装配，页面清单归分册 21）；部署环境配置面（MODULES_ENABLED、SMES_IM_\*、对象存储根目录——无页面，实施期设定）。附件无独立菜单（沿源文档口径，能力只被业务页消费）。

## 3. 业务对象与状态机

实现细节见各包源码与 `architecture/contracts/u-wave/CONTRACT.md` U3 节；本层只列对象与状态语义。

- **附件记录**：`有效 →（remove）→ 已逻辑删除`（不删物理对象；已删记录拒绝签发下载引用）。
- **对象存储引用**：三字段（storageKind/target/objectKey）+ 上传字节 → 端口 put 生成对象键。
- **只读引用令牌**：`签发（TTL 缺省 60s）→ 过期/篡改/对象缺失 → 一律 404 语义`（不区分原因、不泄漏存在性）。
- **打印任务**：`构造（makePrintJob 冻结）→ preview（dry-run 无副作用）→ submit（受理发票）`；外协打印回执 `printed=false` 携拒绝原因，打印失败不炸查询/命令。
- **扫码会话**：`能力探测 → 降级链规划 → 活跃（某档）→ 失败且可降级 → 下一档 → 链耗尽 → 人工兜底`；stop 之后零回调（会话令牌守卫）。
- **IM 渠道**：`按环境装配（wecom/feishu）｜无配置 → console 降级`（不炸 boot）；出站消息 = 文本｜卡片；入站回调经验签（300s 时间窗）后投影。
- **模块装配清单**：MODULES_ENABLED 解析（容忍空白大小写、去重、core 置首）→ 模块注册表装配 → `/demo/ping` 存在性证据。

| 对象 | 状态流转 / 关键态 | 终态语义 |
|---|---|---|
| 附件记录 | 有效 →（remove）→ 已逻辑删除 | 已删不再列示、拒绝签发引用；物理对象永不随删 |
| 只读引用令牌 | 签发（TTL 60s 级）→ 有效 → 过期/篡改/对象缺失 | 一律 404 语义（不区分原因、不泄漏存在性） |
| 打印任务 | 构造（冻结）→ preview（dry-run）→ submit（受理发票） | printed=false 携原因；受理 ≠ 出纸 |
| 扫码会话 | 探测 → 链规划 → 活跃（某档）→ 可降级失败 → 下一档 | 链耗尽 → 人工兜底提示；stop 后零回调 |
| IM 渠道 | 按环境装配（wecom/feishu）｜无配置 → console 降级 | 降级不炸 boot；凭据只入引用不入配置 |
| 模块装配 | MODULES_ENABLED 解析 → 注册表装配/不装配 | 装配即有 HTTP 面，不装配即 404（demo ping 证据） |

验收口径：批量中任一条非法则全批不落；回执顺序与入参一致。锚点：packages/application/src/attachment/attachment.service.ts:103-138、attachment.controllers.ts:51-73；tests/attachment/attachment.test.ts（20 用例绿）。

**RREQ-INT-002 按业务主键挂取附件列表**：GET list-by-biz-id，仅按 bizId 过滤有效记录（不按 bizType——跨表主键唯一由业务侧 id 生成保证），序 createdAt DESC、id ASC；列表 VO 不下发存储三字段（减少暴露）。
验收口径：同上排序；已删记录不出现；VO 无 storageKind/target/objectKey。锚点：attachment.service.ts:141-143、attachment.service.ts:33 注（VO 不下发存储三字段）。
来源：A13 + 源文档二.1｜状态：**已实现**

**RREQ-INT-003 附件逻辑删除**：POST remove，逗号分隔多 id、去重保序；只置逻辑删除标记，不删物理对象；幂等。
验收口径：删除后列表不出现、下载引用被拒。锚点：attachment.service.ts:146-150、attachment-input.ts:196-214。
来源：A13 + 源文档二.4｜状态：**已实现**

**RREQ-INT-004 对象存储端口依赖倒置**：对象字节经 ObjectStoragePort 纯端口 put/签发/解析；本产品形态只落内存与本地文件两个零基建适配器（对象键 upload/日期/uuid 体例；本地适配器路径安全双保险：输入层拒越界段 + 落盘前根目录收敛）；**不引入 MinIO/S3 运行时依赖**，部署期换装适配器不动业务面。
验收口径：put 生成对象键并落字节；越界对象键被拒（双保险）；适配器换装对业务层零改动。锚点：attachment-ports.ts:83-92、local-file-object-storage.ts:63-73/122-128、in-memory-object-storage.ts。
来源：U3 合同（CONTRACT.md §U3）+ A13 方案 B 的端口化重述｜状态：**已实现**

**RREQ-INT-005 短时只读下载引用**：下载不落长期 URL——经端口签发短时只读引用（url+过期时刻+有效秒数+下载展示名）：id+bizId 必填且须与记录一致（防误用他业务附件 id，不一致 409）；拒绝已删记录；downloadName 缺省用附件名；TTL 模块配置化（正整数 1~86400，非法回退 60）。零基建适配器的引用 URL 指回开门面 GET /attachment/storage/:token，令牌为 HMAC-SHA256 能力凭证（claims 含对象键/目标/过期/展示名/内容类型，常数时间比较，过期即失效）；开门面无权限码——令牌即凭证，无效/过期/缺失一律 404 语义。
验收口径：篡改/过期令牌不可换字节；bizId 不一致返回冲突错误；TTL 配置非法回退 60。锚点：attachment.service.ts:157-190、read-reference-tokens.ts:44-87、attachment.controllers.ts:96-120。
来源：A13 + 源文档二.5/1.6 参数表（presignTtlSeconds=60 的模块配置化重述）｜状态：**已实现**

**RREQ-INT-006 上传字节收口与传输护栏**：POST upload——上传字节经端口 put 收口（Cadence 增量面：源文档体系上传在他处完成）；上传体 JSON base64（零新依赖取舍，传输膨胀约 +33%）；字节护栏 32MiB（传输面护栏，非业务大小/类型白名单——白名单本期不做，沿源文档已确认决策）；服务端传输限额 45MiB 对齐；put 成功而登记失败留下孤儿对象（无引用不可达，容忍，物理清理归存储侧运维）。
验收口径：超 32MiB 拒绝并报明确错误；成功上传可经下载引用取回字节。锚点：attachment-input.ts:16-17/91-105、attachment.service.ts:81-100、apps/server/src/main.ts（bodyParser 重注册注记）。
来源：我方增量（U3）+ 源文档 §1.2 已确认决策（不做白名单）｜状态：**已实现**

**RREQ-INT-007 真实对象存储接入（MinIO/S3 适配器与 SDK 预签名）**：部署期提供 MinIO/S3 适配器换装内存/本地文件实现：put 经 SDK 落对象、签发/解析改由对象存储侧签名；等价语义保持——私有桶 + 仅带签名 GET + 下载名随引用下发。
验收口径：换装后业务端点行为不变（六端点回归）；预签名 URL 过期后不可访问；桶/Key 非法返回明确业务错误不泄凭据。
来源：A13（基建接入面）+ 源文档二.5/§五｜状态：**已定义待实现**（差异 A13-a）

**RREQ-INT-008 对象字节层租户隔离前缀**：对象键当前无租户前缀（适配器按实例隔离，tenant 形参留存未用）；接入共享 MinIO/S3 时必须按租户收口对象键命名（如 `{tenant}/upload/...`），否则跨租户对象可枚举/串读。
验收口径：两租户各自上传后，任一租户的令牌解析不可达对方对象（含构造令牌载荷攻击——target 校验 + 前缀隔离双闸）。

## 5. 业务规则与口径

- **附件挂接口径**：列表仅按 bizId 过滤、跨表主键唯一由业务侧 id 生成保证（沿源文档已确认决策，我方一致）；bizType 为单段小写码（源文档 biz_module 字典 1~7 的 ADR-0010 重述——行业绑定值只进数据行）；storageKind 为适配器自述串（源文档 storage_type tinyint 字典 1-MinIO/2-OSS 的通用化）。
- **下载安全口径**：以我方实态为准——短时 HMAC 引用（缺省 60s）等价源文档"私有桶+仅带签名 GET+response-content-disposition"；源文档明确禁止长期直接使用 file_url 拉私有对象，我方 VO 同样不下发存储三字段、file_url 仅展示/兼容。
- **附件鉴权口径**：源文档"预签名本期不做服务端业务鉴权，由页面下载按钮控制访问面"——我方收紧一档：签发需 attachment:read 且 bizId 一致性校验；开门面无权限码（令牌即能力凭证，短时效即约束）。源文档"掌握合法 id+bizId 可换名下载"的风险由 60s 级 TTL 收敛。
- **扫码降级口径**：固定优先序（相机→IM→扫码枪）不可配置（M1 取舍）；串入解析的间隔/时长阈值为站点可配缺省 50ms/2s；码值上限 2048（QR 载荷 GS1/JSON 可超 128——与通用 id 上限分立）；同码去抖窗口 1.5s（相机连续解码逐帧回调只记一次）。
- **打印份数口径**：COPY 编入程序与 job.copies 驱动整份重复**互斥**，接线层必须选定其一（同用相乘）；printed=true = 受理非出纸——验收与运维沟通均按此口径，不把受理当打印完成。
- **IM 凭据口径**：任何配置面不得出现明文凭据（构造期拒绝裸串）；真凭据接入前，算法/哈希/解密类厂商常量刻意不落码（无证据不宣称完成）。
- **PWA 口径**：导航在线优先（NetworkFirst 4s）——离线只承诺离线壳与已访问页，不承诺实时业务数据；复杂策略（BackgroundSync/推送）留正式线。
- **模块启停口径**：core 恒装；缺省集为最小可演示形态，生产按报价单显式开启；启停不影响认证与会话。
- **差异编号口径**：本册新编 D-INT-01 一枚（对象租户前缀）；十三册并行开波若同时新编 D 编号，合流时由总控统一重排，本册占用清单以 §7 为准。
