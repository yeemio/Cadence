# 13 · 工作令与图纸（WO）

版本：v1.0（2026-10-26 冻结）｜编写者：code-writer-pro GLM-5.3（agentId 见回传）｜域码：WO（workorder + drawing）

## 1. 域定位与边界

**身份**：单件流 ETO 的项目档案中心与交付节奏驱动器——每个制造项目一个工作令（洞察 1：每台设备一个工作令），主档挂接客户/项目/销售/项目经理与计划日期，九态状态机（19 条迁移规则）驱动全厂交付主干；图纸（drawing）为随本域交付的专业包子域：版本化文档（append-only 修订链 + 钉版引用 + 保密查看留痕），核心价值 = 版本不乱（洞察 4：图纸就是 BOM）。

- **In（消费）**：工作令主档与九态流转命令；四类清单需求行（listing 只读）、库存可用量（inventory 只读）、进度事实（dispatch/reporting 只读订阅）、客户目录（masterdata）；图纸修订发布载荷与查看请求（许可 clearance）。
- **Out（产出）**：工作令事实与清单骨架创建事件（listing 消费）；齐套快照（dispatch 放行判断）；配件申请审批通过后的出库指令（inventory）；三类进度视图与交付态势（工作台/报表数据源）；图纸修订事实与变更通知（metric-pack 口径升级数据源、挂接方待办）。
- **边界（归属铁律）**：配件申请的功能面展开归 18 册（IS）；四类清单内容与采购口径进度列归 14 册（LP）；派工/报工/质检执行归 16/17 册；工时与成本归集归 19 册；交付报表与下图统计口径归 20 册；移动端入口归 21 册（MB）；附件对象存储/下载通道实施层归 22 册（INT）。

## 3. 业务对象与状态机

| 对象 | 说明 |
|---|---|
| 工作令 WorkOrder | 主档：项目名（必填）+ 客户引用/销售/项目经理/计划交付/包材到货（可空）；id 机器生成（wo-uuidv7） |
| 工作令附件 WorkOrderAttachment | append-only 挂接事实（name/kind/ref）；kind='drawing' 且 ref 按 `drawingId@vN` 钉版编码时进图纸清单装配 |
| 齐套检查 KitCheck | 每次刷新生成不可变快照（三类清单 × 库存可用量的缺口事实，非状态机） |
| 配件申请 PartsRequest | 售后配件单（单物料行），建单即提交；功能面归 18 册（RREQ-IS-031~045） |
| 图纸 Drawing / 修订 DrawingRevision | 版本化文档：一次修订=一条 append-only 修订（fileRef+changeNote+保密等级+supersedes 链） |
| 变更通知 DrawingChangeNotice | 新修订发布联动事实（from→to+changeNote） |
| 查看留痕 DrawingViewTrail | 每次查看的审计行（谁/何时/哪修订/当时等级） |

**工作令九态状态机**（引合同 m2-drafts/02-workorder.md §2；配置驱动可整体替换，ADR-0010 条 2；实态 workorder-config.ts:74-113）：

```
主干 8：not_started → in_progress → ready_to_ship → shipped → in_acceptance
        → in_maintenance → in_aftermarket → completed → closed(终态)
跳态 5：not_started→ready_to_ship；in_progress→shipped（免包装直发）；
        in_acceptance→completed（验收即完成）；in_acceptance→in_aftermarket（免维保段）；
        in_maintenance→completed（免售后段）
回退 6：ready_to_ship/shipped/in_acceptance→in_progress（返工/撤回）；
        in_maintenance→in_acceptance；in_aftermarket→in_maintenance；completed→in_aftermarket（完成重开）
```

- 合计 19 条规则；closed 仅经 close 命令进入（终态语义不被 transition 旁路）。
- 状态机版本（objectVersion）只由迁移推进（创建=1，每迁移+1）；update/attach/kit.refresh 是独立事实不推版本。
- **与源文档九态字典映射**：源字典 1未开始~9已关闭与我方 not_started~closed 一一对应同构；差异见 §5.9（跳态/回退集为我方实态扩展；源文档 toggleDispatch 双向开关仅覆盖主干前两态）。

**配件申请状态机**（对象定义在本域，实态 workorder-config.ts:139-158）：`draft（瞬态初值，建单即 SUBMIT）→ submitted → approved｜rejected(终态) → shipped → received(终态)`——配置六态、业务词汇五态（draft 不停留）；功能需求展开与 S6/D-IS-02 差异归 18 册。

**图纸域无状态机**（版本化文档域）：修订链 = append-only 发布事实；发布 vN+1 不改 vN（钉版引用不漂移）；查看即留痕（审核状态恒 viewed），均为证据列承载。

**分层标注（ADR-0010 三层）**：内核 = 九态状态集与迁移语义、修订链 append-only 纪律与钉版引用语义；模块 schema = 上表实体/命令/事件；默认配置 = 19 规则初版合法集、齐套类目缺省（零件/标准件/电气件）、风险窗口 7 天、保密等级两级值集（public/restricted）。

## 5. 业务规则与口径

1. **状态合法集（19 规则）**：主干 8 + 跳态 5 + 回退 6（§3 图）；closed 仅自 completed 经 close 进入；合法集为初版冻结（02 §8 open question），对账阶段以活系统行为反推校正后整体换配置（ADR-0010 条 2：状态集是配置不是内核）。
2. **目标态寻径**：transition.v1 以目标态寻径（同一目标态可多起点，如 completed 可自验收中/维保中/售后中进入）；证据（kind/ref）≤50 条进事件载荷；备注缺省「流转至 X」。
3. **状态机版本语义**：objectVersion 创建=1、仅迁移 +1；update/attach/kit.refresh 为独立事实不推版本（修订史见 stores 头注取舍）；命令信封 smes.command.v1：operationId 幂等记账 + expectedRevision 乐观锁；创建族命令必 'initial'。
4. **齐套口径**：范围=四类清单缺省三类（零件/标准件/电气件，设备采购类默认不入，模块选项可调）；缺口行=需求量−可用量（下限 0）；快照不可变（每次刷新新事实）；缺口即催办项目经理。
5. **进度口径**：机加工=图号×工序上卷（缺图号行跳过不静默归组）、装配=工序上卷，行状态 done（完成≥总数）/in_progress（有完成）/pending；数据源为 dispatch/reporting 进度事实只读订阅（本域不产执行事实）；风险等级初版口径=逾期/临期（窗口 7 天可注入）/正常，无计划=正常。
6. **配件申请口径**：配置六态、业务五态（draft 建单即 SUBMIT 瞬态初值）；发货出库端口先行（拒绝则整体 rejected 不落账，requestId 幂等）；received 由库存收货联动驱动（本模块不发命令）。
7. **图纸两不变量**：查看必过保密门禁（许可≥等级，值集 v1 两级租户可扩）、查看必留痕（fileRef 唯一取得路径=viewRevision，事件失败 fail-closed）；不可见与不存在同形 404；修订链/清单等元数据面不含 fileRef。
8. **钉版纪律**：修订链 append-only（发布 v4 不改 v3）；引用钉修订号不漂移，升级是显式动作（hasUpdate 只提示不自动改引用）；变更通知发布即联动（from=0 首发）。
9. **与源文档口径不一致处取舍汇总**（均以我方实态为准）：① 源九态字典与我方九态一一同构；但源文档状态迁移仅描述 toggleDispatch（未开始↔进行中）与行内关闭开关，我方为 19 规则配置化状态机（跳态/回退为我方扩展，撤销下派侧未入合法集=S3）。② 源文档一令多设备+设备清单子表；我方单件流一令一设备（洞察 1），设备清单未建（S3）。③ 源文档四进度列=采购/清单口径（购置入库/外购收货+预占/电气入库净量/设备采购合格）；我方三类进度=执行口径（里程碑/机加工/装配）+齐套看板，采购口径归 14 册。④ 源附件=单有效 PDF 替换制；我方=append-only 多附件事实+钉版编码升级（S3 产品化面）。⑤ 源文档工作令号人工唯一；我方机器 id（D-WO-01）。
