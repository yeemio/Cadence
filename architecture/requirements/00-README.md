# Cadence 产品需求文档体系（PRD）

版本：v1.0（2026-10-26 冻结）｜生成：总控会话｜Owner 已批准方案：SRS 形态 / 全量需求化 + 差异登记 / 一波全量并行（GLM-5.3）

## 1. 定位

本目录是 Cadence 的**产品需求规格层（SRS）**，插入在需求源与实现合同之间：

```
需求源（仓外）                    本层（requirements/）                合同层（contracts/）           实现层
73 份源开发文档 ──────对照输入──→  13 分域分册 + 总纲 + 追溯总表 ──引用──→  m2/m3/u-wave 合同  ──────────→  packages/apps
0920 拆解表 109 标准项 ─────────→  （产品语言的需求定义）                        （实现规格）                   （代码+测试）
```

- **源文档只是输入**：本体系用我们自己的产品语言独立成文，不照抄源文档措辞；源文档功能面全部转化为我方需求定义（全量需求化）。
- **不重复合同**：表结构、命令名、端口、事件等实现细节不进本层正文，引用合同文件与锚点。
- **差异只登记不派发**：源文档有而产品暂无的能力，登记为待实现需求（带差异编号），实施仍守 Owner 扩盘刹车（点向才做）。

## 3. 需求项编号与状态

- **需求 ID**：`RREQ-{域码}-NNN`（如 RREQ-WO-001），册内从 001 顺延，不预留空号。
- **状态枚举**（每条需求必标其一）：
  - `已实现`——产品已具备，验收口径列必须给实态锚点（页面/端点/测试或 coverage 锚点，格式同 coverage-matrix 惯例）。
  - `已定义待实现`——我方需求定义已明确、产品暂无；必须挂差异编号（见下）。
  - `部分实现`——已有部分能力，差异列写清缺什么。
- **差异编号**：沿用 DOCS-INVENTORY-DIFF §2 既有编号（A1-A14 / B1-B3 / S1-S14，全局唯一）；新差异用**域前缀编号** `D-{域码}-NN`（如 `D-PE-01`），域内从 01 顺延、跨册不冲突（合流阶段已统一重编，全量清单见 `30-TRACEABILITY.md`）。U 波已交付项（A3/A5 部分/A9/A11/A12/A13 等）按实态标已实现。

## 4. 分册统一体例（七节）

1. **域定位与边界**：一句话身份；In（消费什么）/ Out（产出什么）。
2. **角色与场景**：谁（角色×权限码）在什么场景使用本域功能；桌面/移动入口。
3. **业务对象与状态机**：领域对象清单与状态流转（引合同节，不复制实现细节）。
4. **功能需求项**（核心章）：逐项表/小节，字段固定——
   `需求 ID ｜ 我方定义（明确清晰的产品语言，一句话说清做什么、规则边界）｜ 验收口径（可判定的验收标准；已实现项附锚点）｜ 来源（109 编号 #n / A·B·S·D 编号 / 源文档相对路径）｜ 状态`
5. **业务规则与口径**：状态流转规则、校验闸门、取数口径——产品语言重述；与源文档口径不一致处以我方为准并注明取舍。
6. **跨域关系**：上下游数据流（谁触发我、我触发谁）。
7. **差异与待办登记**：本域全部待实现/部分实现项汇总表（差异编号｜需求 ID｜缺口描述｜源文档出处）——只登记，不排期。

## 5. 口径裁决规则

1. 源文档之间同名口径冲突：以**被引用方节号**（"见《X》三、5"式精确锚点）+ 带「已定稿/评审结论」标记者优先。
2. 我方实态与源文档不一致：**以我方实态为准**写定义，差异节注明取舍（引用合同裁决记录）。
3. 我方合同（m2/m3/u-wave）与本层表述冲突：以合同为实现真源，本层修订——发现冲突时登记进分册差异节并回传总控。
