# 17 · 报工与质检（RQ）

版本：v1.0（2026-10-26 冻结）｜编写者：code-writer-pro GLM-5.3（agentId 见回传）｜域码：RQ（reporting + inspection + 齐套）

## 1. 域定位与边界

**身份**：执行申报与质量门禁——工人把"做了多少"实时记成可核查事实（五类报工三态机+修正链+撤销旁支），四类质检单守入库闸门（判定-放行-不合格闭环-超时点名），齐套核查作为装配/电气开工的前置放行事实。

- **In（消费）**：有效派工单事实（dispatch 只读校验+工艺属性快照来源）、工序合法性与工艺路线末道判定（baseline 端口）、采购收货事实（listing receipt 通道）、库存可用量（inventory 端口，齐套缺口计算）、待办与 IM 基础设施（workbench/integration-im 端口）。
- **Out（产出）**：verified 工时归集与撤销冲销信号（hours）、报工进度上卷与图号×工序进度（workorder/报表）、放行事实（inventory 入库前置）、质检汇总 KPI（工作台/报表）、齐套放行证据（dispatch 装配/电气拦截消费）。
- **边界**：派工/外协单本体归 16（DP）；入库单本体与库存账归 15（IV）；工时账/工时核查审核/成本归集归 19（HC）；订单-收货-退货履约链本体归 14（LP）；报表呈现归 20（RP）；移动端入口归 21（MB）；扫码/IM/打印归 22（INT）。**齐套（KitCheck）实现挂 workorder 域（`kit:refresh`/`kit:read` 端点在 workorder 控制器），但其齐套判定/缺口/放行语义属本域，在本册陈述并对照源文档；拦截执行归 16（DP-003）。**

## 2. 角色与场景

| 角色 | 权限码 | 场景 |
|---|---|---|
| 工人/操作工 | `report:submit` | 按派工单申报数量与工时（单笔/批量，Web 与移动同 API；申报人=本人） |
| 核查员/统计员 | `report:audit` | 待核查单编辑（生成修正版，原因必填） |
| 核查主管 | `report:verify` / `report:revoke` | 报工核查通过与撤销（撤销留痕+冲销信号） |
| 查询角色（各级管理） | `report:read` | 五类列表、详情（修正链全貌+留痕）、我的报工、待核查队列、图号工序进度、产出趋势 |
| 质检员 | `inspection:read` / `inspection:judge` | 四类质检队列、判定、复检、手工建单、超时点名扫描 |
| 质量主管/处置人 | `nonconform:read` / `nonconform:dispose` / `nonconform:close` | 不合格明细查看、处置登记（返工/让步/报废）、闭环 |
| 项目经理/计划员 | `kit:refresh` / `kit:read` | 工作令齐套核查刷新、齐套看板与缺口下钻（端点挂 workorder） |

- 桌面入口：报工管理页（apps/web/src/pages/reporting/ReportsPage.tsx）、报工核查页（…/ReportVerifyPage.tsx）、质检队列页（…/inspection/InspectionOrdersPage.tsx）、不合格处置页（…/NonconformitiesPage.tsx）、齐套看板（…/workorder/WorkOrdersPage.tsx 内嵌）。
- 移动入口（归 21 呈现、API 同源本域）：m.report（申报，离线草稿 FIFO 重放）、m.verify（四类报工核查）、m.mine（我的报工）、m.inspection（四类质检判定/复检）。
- 被动接收：闭环超时点名给判定人（或固定经办人）产生 workbench 待办 + IM 提醒；齐套缺口给项目经理产生催办待办。

## 3. 业务对象与状态机

| 对象 | 说明 |
|---|---|
| 报工单 WorkReport | kind 五类（part/assembly/electrical/aftermarket/oddjob）；挂 DispatchId；完工数量（正数）+工时（整数分钟）+申报人+业务时间；工艺属性（工作令/图号/工序）随单快照 |
| 核查留痕 ReportAudit | 编辑/审核/撤销每次动作一行 append-only（谁、何时、对哪单、改了什么/为什么） |
| 质检单 InspectionOrder | kind 四类（self_outsourced/nonstandard_purchase/standard_purchase/equipment_purchase）；来源对象引用（报工单/外协单/收货单）；送检量+合格/不合格数+判定人时间 |
| 不合格处置 Nonconform | 不合格明细：数量+处置方式（rework/concession/scrap）+原因+闭环状态 |
| 齐套快照 KitCheck | 工作令维度：三类清单（part/standard/electrical）行数汇总+缺口行明细+complete 布尔；append-only 快照（无状态机） |

**报工状态机**（引 contracts/m2-drafts/05-reporting.md §2，配置驱动）：

```
pending ──SUBMIT──▶ reported ──VERIFY──▶ verified（hours 归集锚点）
                        │ │
                        │ └──REVOKE──▶ revoked（终态：hours 冲销信号）
                        └────(verified 亦经 REVOKE)──▶ revoked
```

**质检单/不合格处置状态机**（引 contracts/m2-drafts/06-inspection.md §2）：

```
质检单： pending ──PASS──▶ passed（放行事实）      不合格处置： open ──DISPOSE──▶ disposed ──CLOSE──▶ closed
          pending ──FAIL──▶ failed ──RECHECK_PASS──▶ passed
                              failed ──CLOSE──▶ closed（全部明细闭环联动推入）
```

- 分层（ADR-0010）：状态集与迁移语义归 engine-flow 内核；kind/命令/事件词汇归模块 schema；可报派工状态集、批量上限、末道触发 kind 集、闭环超时阈值、处置枚举为默认配置层（整体替换不改代码）。
- **与源文档状态词汇映射**：源报工模块「未质检/质检中/已质检」挂在质检侧，报工侧源无独立状态机，我方 pending/reported/verified 自成一系；源装配/电气报工「待审批/通过/驳回」↔ 我方 reported/verified/（无驳回态——差异 D-RQ-01）；源采购质检「待质检/已质检/已取消」↔ 我方 pending/passed·failed·closed/（无已取消态——退货侧取消归 LP 域，差异 D-RQ-10）。
- 主键口径：我方品牌化 InspectionId 单主键覆盖四类来源，消解源文档「自制=报工 ID、外协=质检单 ID」双主键二义性（源质检模块 二、1.1.6 专设混合勾选拆请求规则——我方不需要）。

## 5. 业务规则与口径

1. **三态机+撤销旁支**：verified 是主干完成态但保留核查撤销出边（revoked 为唯一终态）；已核查撤销需重报——净额口径由"撤销不计产出+重报单独立计"保证。与源装配/电气"撤销审批→回待审批"（可原地再审）不同，我方不回退（D-RQ-01 取舍：账本 append-only 与重放一致性优先）。
2. **修正链链尾读取**：被 supersedes 的行不进活跃视图，核查命令只作用于链尾；audit-edit 与 verify 是两步（修正版仍待核查）。
3. **ReportVerified 事件形状冻结**：工作令维度（workOrderId/drawingNo/operationCode）+整数分钟 laborMinutes+reporter+businessTime+supersedes；冲销配对=ReportRevoked 同 reportId（fromState 区分是否须冲销）。
4. **净产出口径**：reported+verified 链尾计产出；revoked 与被修正行不计。进度聚合（RQ-012）与趋势（RQ-013）同口径。
5. **超报容忍（现行口径）**：报工数量不硬拦超派工量（合同 05 §8 open question，对账校正）；源文档以精算公式硬拦（S14）——是否引入精算闸门待 Owner 点向（RQ-031/032）。
6. **判定数量校验**：至少判 1 件、合计 ≤ 送检量（允许部分判定）；源为"合格+不合格=送检量"强等式（D-RQ-07 取舍：我方允许分批判定叠加，配合复检刷新；对账阶段如需强等式再收紧）。
7. **放行-入库咬合**：passed 才放行（事件+端口双通道，通知式不阻塞判定）；源"首次质检+零件+末道"三条件入库判定中，末道条件我方前移至触发端（RQ-017），入库侧约束由 inventory 承接。
8. **外协质检触发口径（本册裁定）**：完工投递为准（RQ-018）；下发即建为源差异（D-RQ-05）。
9. **齐套判定口径**：以库存可用量为基数、缺口=max(0, required−available)、快照时点性（刷新制）；源以 reserved（核查预占+入库）≥required 判定并含 MQ 实时联动——两项均为登记差异（D-RQ-11/12），合流后按 Owner 裁定是否换基。
10. **末道判定**：kind∈末道触发集（默认 part）∧ 图号×工序键齐备 ∧ baseline 末道判定真——三条件与源"同一零件已下单工序 sort_order 最大"同构；装配/电气终检扩面经配置整体替换（客户口径未定，见 §8）。
11. **来源触发一律事件/端口驱动+幂等**：同来源对象至多一张活跃待检单；来源对象删除/回退不级联删检单（撤销回退属 D-RQ-04）。
