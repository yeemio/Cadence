版本：v1.0（2026-10-26 冻结）｜编写者：code-writer-pro（GLM-5.3，agentId 见交付回传）｜域码：PE｜验收记录：ACCEPT（code-reviewer GLM-5.3 agent_de0a2a99，2026-10-26）

## 1. 域定位与边界

**身份**：技术准备环节的工艺与设备基线域——"图纸齐、工艺定"之后的工序库、工艺路线、额定工时、物料校验执行、外协计价规则、设备台账与故障闭环的标准基线拥有者，叠加一个按租户显式激活的计划性维保执行域（maintenance 专业包）。

- **In（消费）**：masterdata 物品库（物料校验比对基准，core 模块间端口 ItemStore）；workorder 附件图纸计数（图纸接收进度事实，端口注入）；engine-flow 状态机（故障单/维保任务迁移求值）；workbench 待办与 IM 通知通道（故障派修联动，组合根接线）；approval 审批流（外协计价审批生效的另案挂接点，见 D-PE-06）。
- **Out（产出，不做）**：物料/客户/供应商通用主数据（11 册 MD）；图纸电子化（13 册 WO，M3 图纸包）；清单导入与四清单落库（14 册 LP——物料校验执行由 listing 导入内联触发）；外协派工建单与计价消费（16 册 DP）；报工工序合法性（17 册 RQ）；额定工时对标消费（19 册 HC）；报表口径与呈现（20 册 RP）；移动呈现通则（21 册 MB）；备品备件库存、OEE/能耗（定制，不在产品）。

### 2.2 主场景走查

1. **故障闭环全链**：操作工在车间发现设备异动 → 移动 m.fault 三必填上报（fault:report）→ 单据 open 即派修 assigned，维修工收 IM 推送+待办 → 处置后 Web 端闭环（fault:resolve，备注留痕）→ 待办自动消除；无法处理时 v1 走人工改派口径（拒单命令=D-PE-05）。
2. **维保到期执行**：设备员发布"每 30 天点检"计划（plan-write）→ 到期扫描生成 checkpoint 任务（task-arrange）→ 维修工"我的任务"领单 start → 按判据逐项 pass/fail 留痕（record）→ fail 即待办推送跟进 → complete 收口；任意时点可按设备下钻全量维保历史。
3. **外协取价**：计划员维护工序计价规则（工序单价+利润率，write）→ dispatch 外协派工建单实时取价（active 当前版，price=单价×(1+利润率) 到分）→ 改价=修订新版本行，历史价全程可溯（外协成本对账依据）。
4. **清单导入校验**：清单导入人在 LP 域导入清单 → 导入流程内联触发物料校验（端口）→ 逐行输出匹配/疑似/未匹配+相似度证据 → 校验运行台账可查（material-validation:read），疑似行处置归 D-PE-08 人工介入面。

### 3.2 状态机（engine-flow 配置形态，ADR-0010——状态集是配置不是内核）

- **版本化主数据**（工序/路线/工时/设备/计价规则/维保计划）：写入态 draft → active；superseded 为**推导态**（被任一新行 supersedes 即成立，不落库不可手写）；链不变量：(tenant, code, objectVersion) 唯一、(tenant, supersedes) 唯一（链线性无分叉）；当前版=max(objectVersion)。修订=新版本行，旧行不改（append-only，无删除面）。
- **FaultReport**：`open --ASSIGN--> assigned --RESOLVE--> resolved`（resolved 终态）+ `assigned --REJECT--> open` 回退支（配置已供给、命令面未接入=D-PE-05）；上报即派修（report 命令内完成 ASSIGN），进入 assigned 触发 IM+待办，闭环消待办。
- **MaintenanceTask**：`scheduled --START--> executing --COMPLETE--> done`（终态）+ `scheduled --CANCEL--> cancelled`（终态，仅 scheduled 可撤，executing 不可撤）；建单先落 scheduled@v1 投影再驱动后续迁移。

迁移速查（触发命令 → 进入动作）：

| 对象 | 迁移 | 触发 | 进入动作 |
|---|---|---|---|
| FaultReport | open→assigned | fault.report（命令内即派修） | IM 推送+维修待办 |
| FaultReport | assigned→resolved | fault.resolve | 消待办、备注留痕（终态） |
| FaultReport | assigned→open | （REJECT，命令面未接入=D-PE-05） | 回退待派修池 |
| MaintenanceTask | scheduled→executing | task.start | startedAt 留痕 |
| MaintenanceTask | executing→done | task.complete | completedAt 留痕（终态） |
| MaintenanceTask | scheduled→cancelled | task.cancel | 原因留痕（终态） |
| 版本化主数据 | draft/active→superseded | 修订命令落新行 | 推导态，旧行不改 |

## 5. 业务规则与口径

### 5.1 命令与写路径通用纪律（引 m2 通用合同纪律，产品语言）

- 一切写操作走 smes.command.v1 命令信封：operationId 幂等 / expectedRevision 乐观锁 / 命令动词与端点绑定（防跨资源命令经他端点提交）；P2/P3 端点断言 kind，P1 既有端点行为不动。
- 先解析校验后记账：载荷解析与业务校验全部通过、首个持久写之前 claim operationId——被拒命令不占用 operationId，同 id 改后可重发；已落账同 id 重发拒绝。
- 结果三分：committed / rejected（业务拒绝，含乐观锁失配与并发唯一约束冲突，换新 operationId 重发）/ indeterminate（行已落、事件未落的中断窗口）：版本化主数据与故障线 retrySafe=false（人工对账），维保线事实幂等键完整 retrySafe=true（可安全重放）。
- 租户与操作者身份从不从请求体进（控制器注入，ADR-0005）；查询参数非法 400 显式拒绝，绝不静默丢弃。

### 5.2 工序库口径取舍（vs 源《工序模块-开发文档.md》）

- **以我方实态为准**：①无删除面——append-only 版本链替代源"逻辑删除+被绑定禁删"（禁删语义天然满足；"绑定后仅可改排序"的字段锁定未实现=D-PE-01）；②启停=修订新版本行留痕，替代独立 updateStatus 接口（源文档启停不受绑定限制——我方启停同样不设额外闸门，但每次启停产生版本行，语义等价且可审计）；③类别为自由文本（≤64 字符）而非字典 process_type（D-PE-02）；④无排序号 process_sort（顺序语义由工艺路线步序承载，D-PE-02 一并登记）。
- 源"分页+名称/编码模糊搜索"属呈现层增强（D-PE-02）；selectList+autoOutsource 为清单下单支撑面（D-PE-03）。

### 5.3 外协计价口径取舍（vs 源《外协计价配置-开发文档.md》）

- **量纲与公式不同（D-PE-13 登记）**：我方单价=工序单价（按工序一口价，分）、取价=单价×(1+利润率)；源=市场小时单价（元/小时）+"计划工时/60×小时单价×(1+利润率/100)"公式在派工侧算。我方无"待定"语义（单价必填>0；缺规则=取价 404 fail-closed，等价于"无价不派"）；源利润率默认 20%、我方必填无默认值。
- **生效门槛不同（D-PE-06）**：我方 active 即生效；源须审批已通过且生效时间=审批通过当日（仅记录通过日，不作"到生效日才可引用"门槛——源文档自身已裁决）。取价多条命中的确定性选规（版本号最大、平版本字典序）为我方补充规则，源文档同工序唯一（接口校验）天然无歧义。
- 被引用禁删：我方 append-only 免删除；引用锁定 revise 校验缺=D-PE-07。

### 5.4 物料校验口径取舍（vs 源《物料校验-开发文档.md》）

- **判定模型不同，以我方为准**：源=两态（已匹配/未匹配）+"绑定 material_id"实体模型，匹配=名称+规格 trim 精确一致、多条命中整单失败；我方=三分判定（匹配/疑似/未匹配）+无绑定实体（运行事实行；疑似=suspected 转人工证据位），编码精确+规格归一化 Dice 阈值——判定更宽、证据可校准（阈值对账阶段以行为反推，合同 open question）。"多条命中整单失败"我方不适用（编码路径码唯一至多一命中；名称路径取最高相似度）。
- **架构形态不同，以我方为准**：源=独立校验导入工作台（Excel 建校验单、重复导入不合并、两段式转清单）；我方=listing 清单导入**内联触发**校验（执行走端口、台账只读）。源独立工作台与两段式按功能面分列 D-PE-08/D-PE-11/D-PE-14 登记。
- 源"排除原材料"约束（选料/编辑/新增物料）：属 MD 域物料分类能力+本域 D-PE-08 选料面联动口径，随 D-PE-08 落地时定。

### 5.5 维保口径（引合同 m3/02 §5/§10，产品语言重述）

- 分工铁律：设备台账与故障"报与闭环"在 baseline（标准版能力）；维保包只做计划性执行（任务化留痕）——无维保包时故障上报照常闭环。
- 点检判据 v1=人工 pass/fail+期望文字描述（量化自动判定出现需求时扩数据形状，不进内核）；周期 v1=每日/按间隔天数（按工时/按产量同口径）；fault 已 resolved 而维修任务未 done 的悬挂态提醒为合同开放问题（§8-3）。

### 5.8 对账锚点清单（两合同 Done-when/对账要点的产品语言重述）

- 外协计价：外协单取价=工序单价×(1+利润率) 数值一致（half-up 到分）。
- 维保到期：同计划集合同周期的到期任务生成集合一致（含日保/间隔保，幂等重扫零追加）。
- 维保留痕：三态记录留痕与修正冲销行为等价（append-only，不改原行）。
- 故障联动：fault→维修任务→restored 全链行为等价；计划改版后历史记录溯源旧版可解释。
- 开关：维保关闭时全链路不可见且 baseline 故障上报不受影响。
