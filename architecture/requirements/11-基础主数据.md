## 1. 域定位与边界

**一句话身份**：五类基础主数据（物品 / 资源 / 客户 / 供应商 / 计量单位）的租户级单一事实源——全产品业务单据引用的"人、机、物、对手方、量纲"档案层。

- **In（消费什么）**：无上游业务输入；仅消费租户身份（数据按租户收口）与操作者权限码。本域是全产品的数据源头之一。
- **Out（产出什么）**：五类主数据档案及其编码唯一性 / 启停语义，供清单（四类清单、物料校验）、库存、派工外协、采购、工作令等域引用选料 / 选对方；本域不产出业务事实，也不接收业务回写（库存数量等汇总不落物品档案，见 §5.8 / §7.2）。
- **实态锚点**：模块 `packages/application/src/masterdata/`（端口 `masterdata-stores.ts` / 用例 `masterdata.service.ts` / 路由 `masterdata.controllers.ts` / 输入解析 `masterdata-input.ts`；PG 适配 `packages/business-store/src/masterdata/pg-masterdata-stores.ts`，RLS 租户行隔离）；桌面页 `apps/web/src/pages/masterdata/`（五页）；coverage `architecture/coverage/coverage-matrix.md` §2 基础信息域行（#8/#9/#11）与 §2 后段（#100）。
- **域边界**：物料校验（#12）、外协计价配置（#13）虽列 109 表基础信息段，但实态归 baseline 域（12-工艺与设备 / 14-清单与采购各册定义）；设备档案与维保归 12-PE；本册只覆盖 `masterdata` 模块五类主数据。
- **非目标（本期）**：分页/筛选、导入导出、价格台账族、扩展属性——全部登记于 §7.1 差异表，只登记不派发（00-README §8 刹车红线）。
- **术语对照**（源词 → 我方词，全文适用）：物料 Material → 物品 Item（ADR-0010 通用词）；material_status 启用/禁用 → active 布尔；计量单位简写 → symbol 符号；供应商合作状态 → active 布尔（近似承接，见 §7.2）。

## 3. 业务对象与状态机

| 业务对象 | 我方定义（一句话） | 租户内唯一键 | 启停 | 合同锚点 |
|---|---|---|---|---|
| 物品 ItemMaster | 通用"物"的档案：原料 / 半成品 / 成品 / 辅料等，分类由 category 自由描述 | code | active 双态 | `masterdata-stores.ts:20-65` |
| 资源 ResourceMaster | 通用"产能资源"档案：设备 / 工位 / 人员组等，类型由 type 自由描述 | code | active 双态 | `masterdata-stores.ts:67-98` |
| 客户 CustomerMaster | 工作令选用的交易对手方档案 | code | active 双态 | `masterdata-stores.ts:109-139` |
| 供应商 SupplierMaster | 外协厂家与供货商合一的对手方档案（供外协派工与采购引用） | code | active 双态 | `masterdata-stores.ts:141-168` |
| 计量单位 UnitMaster | 纯字典：编码 / 名称 / 符号（无停用语义，见 §5.4 取舍） | code | 无 active | `masterdata-stores.ts:171-198` |

**状态机**：物品 / 资源 / 客户 / 供应商为 `启用 ⇄ 停用` 双态布尔（创建缺省启用；两向均不设引用限制——与源物料启停口径一致，源客户无启停、源供应商为"合作中/暂停中"两值字典，取舍见 §7.2）。**五类均无删除态**——存储端口不设删除操作（`masterdata-stores.ts:13-15` 设计取舍：主数据将被事务表引用，硬删引入悬挂引用；下线路径 = 停用）。启停与修正即时生效、不经审批流（配置数据非业务事实，不进审批链）。

**数据形态裁决**：主数据 / 配置数据不是业务事实——不套证据公共列、不套 append-only / 冲销修正链（修正 = 直接改行；总纲 §5.8 的域内细化，纪律只约束事实表）。code 为租户内唯一人读稳定码，创建后永不可变。创建 / 修改 / 停用不产出领域事件（本域无生命周期事件面，消费方按需读列表）。

**字段速览**（五对象共有骨架 = id/tenant/code/name + 各自扩展；校验锚点 `masterdata-input.ts`）：

| 对象 | 必填字段 | 可选字段（上限） | 特殊取舍 |
|---|---|---|---|
| 物品 | code（1~64 稳定码）、name（1~128） | spec（≤256）、unit（≤64）、category（≤64）、active | unit/category 自由文本，行业词只进数据不进代码 |
| 资源 | code、name | type（≤64）、active | type 自由描述设备/工位/人员组 |
| 客户 | code、name | contact（≤256）、active | 电话/邮箱/地址合一自由文本 |
| 供应商 | code、name | active | 扩展画像字段见 RREQ-MD-028（待实现） |
| 计量单位 | code、name | symbol（≤32） | 无 active（字典无停用语义） |

id 为存储侧生成的不透明串（PG 侧 uuidv7），不承载业务含义，路径参数仅做非空 / 无空白形状校验（`masterdata-input.ts:181-187`）；人读稳定性全部由 code 承担。

**引用方向**：五类对象均被他域单向引用；本域对象不持有任何他域外键（无工作令 / 库存 / 采购引用字段）——源头纯粹性是本域边界裁决的基准。

## 5. 业务规则与口径

1. **唯一性与稳定键**：code 是唯一的租户内唯一键与稳定键（创建后不可变，更新携带即 400 拒绝）；名称不参与唯一性——同一名称可在不同 code 下并存，人读歧义由 code 消解（源系统物料按"名称+规格"、客户按名称、供应商按"类型+名称"组合唯一，我方统一为 code 唯一，取舍见 §7.2）。
2. **期望态更新**：更新请求未携带的键一律不动；可选文本 null/纯空白 = 清空；空更新体合法（幂等无操作）。
3. **删除语义（域内裁决）**：五类均无删除。源系统三类"被引用禁删"校验（物品六源 / 客户-工作令 / 供应商-生产购置清单）与"被引用锁名称/规格"在我方由"无删除端点 + code 稳定"结构性消解；下线路径 = 停用。此为 00-README 口径裁决规则第 2 条的应用（我方实态为准）。
4. **启停语义边界**：启停两向均无引用限制（停用不迁移不阻断历史单据）；"选料仅启用行"是消费域取数规则（清单/派工/采购各册定义），本域只保证 active 随列表行返回。计量单位无停用（字典改错即改名）。
5. **错误语义**：输入非法 400（绝不静默丢弃）、目标不存在 404、code 冲突 409（域错误族 `masterdata-errors.ts:12-33`，HTTP 映射由组合根异常过滤器承担）。
6. **跨租户隔离**：所有读写按租户收口，跨租户 id 不可见（等价不存在）；PG 侧叠加 RLS 行隔离（`pg-masterdata-stores.ts` 头注）；遵循总纲 §5.1 fail-closed。
7. **持久形态**：启动零 DB 依赖——无数据库连接时回落内存实现，有连接走 PG 适配（同一端口合同，行为一致）。
8. **库存汇总不回写**：源系统在物料表维护三列仓库库存汇总（业务回写）；我方口径：库存数量归 15-仓储与库存域台账，不回写物品档案（本域无此字段面，取舍见 §7.2）。
9. **取数排序**：列表当前无显式排序承诺（全量返回，呈现顺序由存储决定）；源系统"更新时间降序"排序口径随 RREQ-MD-024 一并考虑。
10. **唯一性双保险**：应用层预校验之外，持久层唯一约束冲突（Prisma P2002）翻译为同一 409 域错误（`pg-masterdata-stores.ts:42-48`）——并发同码创建不会穿透为 500。
11. **流程边界**：主数据建档 / 修正 / 停用均不进审批流（§3 配置数据裁决），与 10-SYS 审批配置无接线；操作留痕由系统审计面统一承担，不在本册单列。
