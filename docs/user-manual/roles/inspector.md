# 质检岗（inspector）操作手册

事实快照日 2026-10-27（同日 M2-R1 增量后更新：判定撤销桌面入口、特采类别前端闸、不合格详情中文化）。来源：`architecture/ROLE-PACKS.md` §1.4；`noodle-test-output/ui-round2-20261027/Cadence-ui-round2-20261027-report.md` §4/§6（特采按钮实态）；菜单与按钮名以系统实态为准。

## 职责

四类质检单（含采购来料、末道报工、外协回厂、手工）的判定/复检、特采让步、判定撤销与不合格处置闭环。质检是放行入库的闸门：只有质检判定合格/特采放行的物料，仓管才能执行「质检放行入库」（入库需引用质检单号）。

## 权限与菜单入口（7 码：基线 2 + 岗位 5）

| 能做什么 | 菜单入口 | 说明 |
| --- | --- | --- |
| 查质检队列/汇总 | 质量管理 → 质检队列 `/inspections` | 待检/合格率/未闭环汇总卡 |
| 建质检单、判定、复检、批量判定、超时点名 | 队列页各按钮 | 建单四要素：类别、送检数量、来源类型、来源对象编号 |
| 不合格明细查看 | 不合格处置 `/inspections/nonconformities` | 「执行处置」（返工/让步/报废 + 原因必填）、「闭环」 |
| 特采（非标件） | 质检单不合格后的「特采」按钮 | 仅非标件采购类质检单可采（其他类别按钮呈「不适用」说明）；受剩余量闸约束；走特采命令通道 |
| 判定撤销 | 质检单详情「判定撤销」按钮（M2-R1 新增桌面入口） | 已质检单（合格/不合格态）可撤：回待检、清空判定字段；不合格明细随之作废（已结案保留）、特采累计清零、放行收回 |

**明确没有**：入库执行（归仓管，判定与入仓两岗分离）、报工核查、齐套刷新。

## 典型日操作

1. **看队列**：质检队列页看汇总卡（待检/合格率/未闭环）→ 状态过滤选单。
2. **建单**（自动触发之外的场景）：「手工建质检单」→ 选类别（四类）、送检数量、来源类型（报工/外协回厂/采购收货/手工）+ 来源对象编号 → 提交。
   - 注意：质检建单当前**没有「直接挂工作令」字段**（页面文案已注明「直接挂工作令暂未开放」）——通过来源对象编号间接关联（如末道报工单本身归属工作令）。属已登记限制（QC-02）。
3. **判定**：选中单 → 填合格数/不合格数 →「判定」。不合格数 > 0 自动生成不合格处置明细。判定有误走「复检」改判。
4. **特采（让步放行）**：非标件采购类质检单判不合格后点「特采」，按剩余量闸与配额回显操作。其他类别（自制外协/末道报工/手工等）特采不适用，按钮处会给出「特采仅适用于非标件采购质检单」的说明（服务端同口径约束）。
5. **判定撤销**：质检单详情 →「判定撤销」→ 填撤销原因（可留空，留空按系统默认留痕）→ 两步确认（确认框讲明后果）→ 提交。成功后单据回到待检态，流转记录出现「撤销质检」条目，可重新判定。
6. **处置闭环**：不合格处置页 → 选中明细 → 选处置方式（返工/让步/报废）+ 填原因（必填）→「执行处置」→ 全部明细处置完后「闭环」。
7. **超时点名**：队列页「闭环超时点名」扫超时未闭环单（联动通知/IM 推送）。

## 常见拒绝与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 找不到要检的单 | 该来源未触发自动建单（如部署方裁剪了末道工序类型配置），或来源对象编号填错 | 手工建质检单，填对来源类型与来源对象编号 |
| 合格数 + 不合格数 ≠ 送检数量 | 数量校验 | 两数之和须等于送检数量 |
| 特采按钮点了没反应/提示不适用 | 特采仅适用于非标件采购类质检单；其他类别按钮处有「不适用」说明（前端闸与服务端同口径） | 属设计内限制；非标件让步需求先与管理员/实施方评估 |
| 特采被拒绝 | 剩余量闸：可让步余量不足 | 核对剩余量；不可超量让步 |
| 判定想撤回 | 已质检单（合格/不合格态）可撤 | 质检单详情「判定撤销」→ 填原因 → 两步确认。未质检（待检）与已闭环（终态）不可撤，页面会给对应说明 |
| 撤销被拒绝 | 跨域闸门拦截（关联入库未完成/下道工序已报工或已质检/工时已审核）或单据状态已被他人变更 | 按页面提示刷新列表核对该单当前状态与版本后再决定；不要重复盲提交 |
| 处置/闭环被拒 | 原因必填、明细须全部处置后才能闭环 | 补原因；逐条处置完再闭环 |
