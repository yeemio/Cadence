# 只读观察岗（observer）操作手册

事实快照日 2026-10-27。来源：`architecture/ROLE-PACKS.md` §1.7 与 §0「demo 先例」；以系统实态为准。

## 职责

全业务面只读观察者：所有列表与详情可见、零写权限，任何提交动作被后端拒绝。适合项目观察、审计随行、测试见证。

## 两种「只读」形态（不要混淆）

| 形态 | 权限构成 | 表现 | 来源 |
| --- | --- | --- | --- |
| **观察形态**（本岗位包 observer） | 服务端全部 48 个读码 + 前端扫码菜单码，共 49 码，0 个写码 | 全业务菜单组与页面可见，浏览一切；提交即 403 | `architecture/ROLE-PACKS.md` §1.7 |
| **拒绝形态**（种子 viewer 账号） | 无任何授权策略 | 登录可以、业务菜单基本全隐、直接访问深链被拒；用于演示/验证「权限拒绝」 | `packages/business-store/prisma/seed-factory.mjs` 头注、`TESTING-GUIDE.md` §3 |

种子/演示环境默认只有 viewer（拒绝形态）。需要观察形态的 observer 账号，由管理员按 ROLE-PACKS §1.7 的码集开通（见 [admin.md](admin.md)）。

## 典型使用方式

1. 登录 → 左侧菜单逐组展开（基础数据/制造运营/报工管理/采购管理/质量管理/仓储管理/成本与工时/标准报表/图纸文档/工艺与设备/系统管理）→ 浏览列表与详情。
2. 建议与操作岗同时在线（另开浏览器画像），全程跟看单据状态变化。
3. 权限验证用法：在任意页尝试提交（如点「创建派工单」再提交）→ 预期得到后端 403 / 错误提示，页面按钮不做按角色隐藏是设计内口径（防线在后端）。

## 常见疑问

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 某页面看不到 | 该页面挂在写码或非读码下（读码覆盖为服务端全部查询面；个别前端专属菜单码如扫码页 observer 已含） | 属权限投影，不是故障 |
| 提交报 403 | 本岗位零写码（设计内） | 不需要处理——这正是该岗位的验证点 |
| viewer 深链打开仍渲染表单 | 已登记缺陷（UX-VW-R2-01：viewer 深链写表单渲染、按钮 enabled） | 不提交即可；修复前以提交被拒为准，见 KNOWN-BEHAVIORS |
| 菜单里「移动报工」点开是说明页 | 桌面移动报工是引导页（设计内） | 见 [../getting-started.md](../getting-started.md) |
