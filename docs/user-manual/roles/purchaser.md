# 采购岗（purchaser）操作手册

事实快照日 2026-10-27。来源：`architecture/ROLE-PACKS.md` §1.2；菜单与按钮名以系统实态为准。

## 职责

把缺口变成订单：从缺口或手工发起采购申请，建单、提交、跟进下发与收货，办理退货。订单的**审批**归审批岗（本岗不能自己批自己的单）；供应商等主数据维护归管理员/主数据岗。

## 权限与菜单入口（9 码：基线 2 + 岗位 7）

| 能做什么 | 菜单入口 | 说明 |
| --- | --- | --- |
| 查采购四页（申请/订单/退货/明细） | 采购管理 组 | 状态过滤：申请 draft/approved/converted；订单五态 |
| 发起采购申请 | 采购申请页「提交采购申请」 | 从缺口或手工发起 |
| 建单并提交、下发订单 | 采购订单页 | 承接申请；下发/逾期扫描 |
| 收货入库 | 订单页「收货入库」按钮；菜单叶子「采购收货」`/purchase/receiving` | 录行号/数量/收货单号；与仓管岗共码（小厂双人经办口径） |
| 建退货单/撤销退货 | 采购退货 `/purchase/returns` | 针对已收货订单 |
| 查供应商、查物品 | 基础数据 → 供应商 / 物品 | 建单需供应商引用；只读 |

**明确没有**：订单审批（`purchase:approve` 归审批岗）、缺口核查（归计划）、供应商写维护。

## 典型日操作

1. **发起申请**：采购申请页 →「手工发起采购申请」→ 选类别、物料、数量（可挂工作令）→ 提交。计划岗缺口核查产生的缺口行是本步的常见输入。
2. **建单**：采购订单页 →「建单并提交采购订单」→ 填供应商引用/名称、**交期（必填，ISO 日期格式）**、至少一行物料+数量、备注与关联配件申请（如有）→ 提交。订单进入「已提交」待审批。
3. **跟进**：工作台看逾期催货待办（采购逾期自动生成催货待办）；订单页按状态过滤跟催。
4. **收货**：订单审批通过并下发到货后 →「收货入库」→ 填收货行号、收货数量、收货单号。
5. **退货**：退货页对已收货订单建退货单；撤销退货同页。

## 常见拒绝与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 建单时交期校验失败 | 交期必填且为标准日期格式 | 按页面提示格式填写 |
| 「审批通过」按钮点了报 403 | 审批归审批岗，本岗无该权限（设计内分权） | 通知审批岗处理；在工作台/通知跟进状态 |
| 收货仓库只能手填编码，不是下拉选择器 | 已登记体验缺陷（UX-PUR-03 一部分），当前收货仓库为编码文本框 | 按仓库编码准确填写（如缺省 `MAIN`）；写错会被库存侧校验拒绝 |
| 「关联采购申请」字段是自由文本 | 同属 UX-PUR-03 已登记项 | 填申请编号文本即可，不影响流程 |
| 对已收货订单重复收货 | 行收货数量受订单行数量约束 | 按剩余量收货；多退少补走退货 |
| 单价填错量级 | 单价按**元**填写（输入 128.50 = 128.5 元，内部存 12850 分）；超大误输有预检拦截 | 见 [../getting-started.md](../getting-started.md) 通用约定 |
| 单号很长显示为「头8…尾4」 | 短码显示约定 | 引用给他人时注意复制得到的是短码（已知使用注意，见 KNOWN-BEHAVIORS） |
