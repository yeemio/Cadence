# 管理员操作手册

事实快照日 2026-10-27。来源：`architecture/ROLE-PACKS.md` §0「开通路径」与 §3（管理员域权限码清单）、`architecture/contracts/m2-security/CONTRACT.md`（SP-1/SP-4）、`apps/server/src/main.ts`（env 接线实态）；以系统实态为准。

## 职责与权限定位

管理员不受七岗位包约束：种子 `admin` 账号是全量放行形态（权限判定三级：精确码授权 → 角色投影 → admin 全量放行）。管理域动作包括：组织/账号/角色/部门/岗位、菜单与审批流配置、主数据维护、工时成本薪酬运行、主管跨岗动作（报工核查、工作令流转/关令等）、审计与会话观察。

日常建议：管理员只做「开通与配置」，业务单据操作走各岗位账号——这样既能验证权限边界，也避免把管理旁路当成日常流程。

## 岗位开通（给新岗位/新员工配权）

1. **建角色**：「系统管理 → 角色与授权」页（`/system/roles`）→ 新建角色 → 按目标岗位的权限码清单**期望态一次提交**——服务端自动比对差量增授/回收，不需要逐条勾选反复提交。七个标准岗位的码集见 `architecture/ROLE-PACKS.md` §1（计划 13 / 采购 9 / 生产 11 / 质检 7 / 仓管 17 / 审批 8 / 只读观察 49，含全员基线两码）。
2. **绑用户**：「系统管理 → 用户与角色」页（`/system/users`）→ 新建用户（初始口令受口令策略校验，见下）→ 绑定角色。
3. **验证**：让该用户登录，核对菜单可见范围与预期岗位包一致（菜单可见 = 接口可达）。

## 口令策略与口令重置（当前实态）

- **策略只在设置口时校验**：新建用户初始口令与重置口令两个端点校验；**登录不校验**（存量弱口令仍可登录，出清靠管理员逐个重置）。
- 缺省最小长度 **8**（env `SMES_PASSWORD_MIN_LENGTH` 可调，部署方配置）；字符类要求（大小写/数字/符号）缺省关闭（env `SMES_PASSWORD_REQUIRE_CLASSES=on|off`）；上限 128。
- 拒绝时提示含策略要求。演示口令 `demo-password`（13 字符）满足缺省策略。
- **重置口令后该用户所有已登录会话立即全部失效**（写时全端撤会话）——重置前告知当事人。
- （来源：`architecture/contracts/m2-security/CONTRACT.md` SP-4 范围；`apps/server/src/main.ts` L133-145）

## 审批链配置

配件审批链级数是**部署配置**（env），不是页面配置：`SMES_PARTS_APPROVAL_LEVELS`（1|2|3，缺省 1 单级）+ 二/三级参数角色名（org 角色码，单段小写）。多级链的角色**授权**（给角色挂 `parts:approve`）在角色页完成。配置细节见 [../../../deploy/README.md](../../../deploy/README.md) 环境变量表；审批人视角见 [approver.md](approver.md)。

## 主管跨岗动作（七岗位包之外的处置权）

以下动作在七岗位包中没有对应岗，需要时由管理员执行（或另立管理岗授权）：

| 动作 | 入口 | 说明 |
| --- | --- | --- |
| 报工核查/审核/撤销冲销 | 报工单 `/reports`（「核查通过」「提交修正版」「撤销冲销」按钮） | 核查链；业务链主线不含此环节 |
| 工作令九态流转 | 工作令详情「执行流转」 | 项目经理/管理岗终裁 |
| 关闭工作令 | 工作令详情「关闭工作令」 | 同上 |
| 主数据维护 | 基础数据组各页（物品/客户/供应商/单位/资源等写维护） | 七岗位包只有读码 |
| 工艺/标准工时/设备/维保/薪酬/成本重建 | 相应菜单组 | 属管理域 |
| 审批流配置 | 审批配置页（approval-config） | 非审批人日常 |
| 菜单配置 | 菜单配置页（menu-config） | 自定义菜单名在任何语言下按原文显示、不翻译 |

## 常见拒绝与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 角色保存后用户菜单没变化 | 用户需重新登录刷新会话与权限投影 | 让用户退出重登 |
| 建用户/重置口令被拒 | 口令策略：长度不足或字符类不符 | 按提示调整口令 |
| 多级审批演练时 L1 批准 403 | 种子 plan 角色缺 `parts:approve`（已登记缺陷 AP-SEED-01） | 在角色页给 plan 角色补 `parts:approve` 后重试 |
| 演示账号太多想批量开 | 无批量开通界面 | 逐个开通；工厂种子可一次性提供六岗演示账号（见 [../demo-handover.md](../demo-handover.md)） |
| 需要锁定某账号/手动解锁 | 管理员手动锁定/解锁未实现（登记的后续议题）；登录锁定仅按失败次数自动 15 分钟 | 临时处置：重置口令（全端撤会话） |
