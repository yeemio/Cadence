# 审批岗（approver）操作手册

原快照日 2026-10-27；2026-10-31 对齐采购分级批准和 P2-06 配件审批证据。来源：`architecture/ROLE-PACKS.md` §1.6；`architecture/status.md`（S6 三级审批、18 册增补 #1 实态）；菜单与按钮名以系统实态为准。

## 职责

原审批岗负责配件申请及通用审批案件；**新采购订单已改由制造控制台的财务 E13 复核、运营 E02/总经理 E01 分级批准**。原 `appr01`/`purchase:approve` 不自动获得这些职责，也不能从旧订单按钮直接批准。采购发起/报价、复核、批准分人；旧配件链按工作令项目经理及部署级数判定，不与采购链混用。

## 配件审批多级链（当前实态，重要）

- 缺省**单级**：一级审批人=项目经理口径（manager，回落 salesRep）。
- 二/三级由**部署方以环境变量配置参数角色**（`SMES_PARTS_APPROVAL_LEVELS` 1|2|3 + `SMES_PARTS_LEVEL2_ROLE` / `SMES_PARTS_LEVEL3_ROLE`）启用；二/三级为**或签**（该级参数角色下任一持权人可批）；待审批人按角色**实时解析**、不落库（换人不需改单）。
- **只有一级（L1）已审且轮到本级时才能批**：未轮到本级时，移动端按钮有点击前预警，提交会被拒绝并给出主语化拒因（「谁」因为什么拒绝）；按钮不做硬禁用（设计取舍，以提交反馈为准）。
- 配置错误（配了多级却没配角色名）服务端启动即失败，不会静默按单级跑。
- AP-SEED-01 已修：当前工厂种子给 `plan01` 所属计划角色 `parts:approve`，因为该账号兼任夹具工作令项目经理。2026-10-31 缺省单级链隔离读回已证明它可批准；制造运营 E02 未获原配件权限时仍为403。旧环境核对实际权限，不重跑种子改历史，也不把这条配件证据推广为采购自批或全部多级链通过。

## 典型日操作

1. 工作台看待办概览（来源计数）与我的待办（审批类）。
2. **采购交接**：收到采购 E08 报价后，由财务 E13 在制造控制台「采购净额」核定需求并「独立财务复核」；再由不同自然用户按当前累计阈值批准。本单或同需求累计净额超过10万元须 E01，否则 E02；批准后交采购下发。原审批岗只承担其已获权限，不以旧采购页按钮代替这条链。详见[采购岗](purchaser.md)。
3. **配件申请审批**：配件申请页 → 过滤「已提交」→ 粘贴目标申请编号 → 填决策理由 →「批准」/「驳回」；移动端 `/m/parts-approval` 待审列表逐单决策（同径）。

## 常见拒绝与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 配件点批准报 403 | 旧环境可能未有实际审批权，或当前账号不是原配件链的有权处理人；本版 plan01 种子缺权已修 | 核对该工作令项目经理、当前级与现有授权，交原责任岗；不直接换成制造运营 |
| 提交被拒「未到本级」 | 多级链下 L1 未审完或未轮到本级（实时解析，设计内） | 等前级审批；页面预警与拒因会说明当前级与审批人 |
| 旧采购「审批通过」被拒 | 该入口不能绕过当前净额复核和分级批准，即使订单已提交 | 转制造控制台按本版复核/批准；配件审批仍用原入口 |
| 决策理由未填被拒 | 理由必填（留痕要求） | 补理由 |
| 桌面找不到审批箱 | 通用审批案件无独立桌面页（设计内），经工作台待办联动 | 从工作台待办进入 |
| 配件详情提示「响应形状非法」 | 已登记观察项（AP-OBS-03：已批准后桌面详情报错） | 以列表状态与移动端为准；见 KNOWN-BEHAVIORS |
| 成功提示是「审批已提交成功。」而非「操作已生效」 | 文案不统一（已登记观察项 AP-OBS-04） | 属正常提交成功，不影响结果 |
