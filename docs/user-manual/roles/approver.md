# 审批岗（approver）操作手册

事实快照日 2026-10-27。来源：`architecture/ROLE-PACKS.md` §1.6；`architecture/status.md`（S6 三级审批、18 册增补 #1 实态）；菜单与按钮名以系统实态为准。

## 职责

审批闸门：采购订单审核、配件申请多级审批、通用审批案件决策，经工作台待办驱动。审批人不建单（建单归采购）、不发起申请（申请与审批分权——申请人不批自己的单）。

## 权限与菜单入口（8 码：基线 2 + 岗位 6）

| 能做什么 | 菜单入口 | 说明 |
| --- | --- | --- |
| 看待办 | 工作台 `/`（本人待办 + 来源计数）；顶栏通知 | 审批类待办联动 |
| 通用审批案件查询/决策 | API 面（GET/POST /approval/*） | 桌面无独立审批箱页，案件经工作台待办联动 |
| 看采购订单 | 采购管理 → 采购订单 `/purchase/orders` | 审批前提是订单可见（只读） |
| 订单审批 | 订单页「审批通过」按钮 | **决策理由必填**，留痕 |
| 看配件申请 | 配件申请 `/workorders/parts` | 列表含当前级/审批人/流转信息 |
| 配件申请审批 | 同页「批准」「驳回」；移动端 `/m/parts-approval` 同径 | 多级链实态见下 |

**明确没有**：采购建单/下发、配件申请发起与发货联动、审批流配置（归管理员）。

## 配件审批多级链（当前实态，重要）

- 缺省**单级**：一级审批人=项目经理口径（manager，回落 salesRep）。
- 二/三级由**部署方以环境变量配置参数角色**（`SMES_PARTS_APPROVAL_LEVELS` 1|2|3 + `SMES_PARTS_LEVEL2_ROLE` / `SMES_PARTS_LEVEL3_ROLE`）启用；二/三级为**或签**（该级参数角色下任一持权人可批）；待审批人按角色**实时解析**、不落库（换人不需改单）。
- **只有一级（L1）已审且轮到本级时才能批**：未轮到本级时，移动端按钮有点击前预警，提交会被拒绝并给出主语化拒因（「谁」因为什么拒绝）；按钮不做硬禁用（设计取舍，以提交反馈为准）。
- 配置错误（配了多级却没配角色名）服务端启动即失败，不会静默按单级跑。
- 已知种子缺口：工厂种子环境里 plan 角色未配 `parts:approve`，L1 待审时点批准会 403（已登记缺陷 AP-SEED-01，多级链演示需管理员临时补权）。见 [../KNOWN-BEHAVIORS.md](../KNOWN-BEHAVIORS.md)。

## 典型日操作

1. 工作台看待办概览（来源计数）与我的待办（审批类）。
2. **订单审核**：采购订单页 → 过滤「已提交」→ 选中 → 填决策理由 →「审批通过」（驳回同理；理由留痕）。
3. **配件申请审批**：配件申请页 → 过滤「已提交」→ 粘贴目标申请编号 → 填决策理由 →「批准」/「驳回」；移动端 `/m/parts-approval` 待审列表逐单决策（同径）。

## 常见拒绝与恢复

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点批准报 403 | 当前账号/角色未被授予 `parts:approve`（如种子 plan01 的 AP-SEED-01 缺口） | 管理员补授权后重试；见 KNOWN-BEHAVIORS |
| 提交被拒「未到本级」 | 多级链下 L1 未审完或未轮到本级（实时解析，设计内） | 等前级审批；页面预警与拒因会说明当前级与审批人 |
| 「审批通过」按钮对非「已提交」单可用但提交失败 | 按钮不做状态硬禁用（设计取舍），防线在后端 | 只对「已提交」态单操作 |
| 决策理由未填被拒 | 理由必填（留痕要求） | 补理由 |
| 桌面找不到审批箱 | 通用审批案件无独立桌面页（设计内），经工作台待办联动 | 从工作台待办进入 |
| 配件详情提示「响应形状非法」 | 已登记观察项（AP-OBS-03：已批准后桌面详情报错） | 以列表状态与移动端为准；见 KNOWN-BEHAVIORS |
| 成功提示是「审批已提交成功。」而非「操作已生效」 | 文案不统一（已登记观察项 AP-OBS-04） | 属正常提交成功，不影响结果 |
